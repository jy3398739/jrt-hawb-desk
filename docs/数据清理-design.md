# 数据清理（彻底删除已作废的票）· 设计

日期：2026-10-11　版本目标：v1.14.0　状态：已与用户确认，待实现

## 1. 要解决的问题

台账与统计里积着测试票与历史票。v1.11.0 给的「作废」是软闸门——它只把行从台账与正确率里收起来，
**票面原件与全部解析产物还在服务器上**。用户要的是：作废过、且放够了日子的票，能一次挑出来彻底删干净。

三条已确认的口径：

- **候选只有「已作废且满 N 天」的票。** 这是本功能唯一的不变式，服务端与界面都按它走。
- **彻底删 + 留一行删除凭据**（`output/purged.jsonl`，只追加）。凭据里只留"这张票存在过、删之前台账长什么样"，
  不留任何收发货人 / 货物 / 地址内容。
- **仅管理员。** 门禁落在服务端（`require_admin`），顶栏按钮 `hidden` 只是配套，不是防线。

## 2. 入口与界面

独立的浮层「数据清理」，与「统计」「账号管理」同一套壳（`.gate` + `.card`），顶栏一颗仅管理员可见的入口，
上面挂候选数字徽标（「清理 3」）。

**为什么不开在统计窗口里**：统计窗口顶部那对日期框是"算哪些票"的分析窗口，保留期是"作废多久之后允许抹掉"——
两个含义不同的时间轴并排摆，就会出"改了保留期怎么统计行数也变了"这类误判（同之前上传/解析时间混淆一族）。
分开摆，各自的时间控件含义唯一。

面板内容：

1. 顶部常驻一句说明（不是弹一次就走）：删除不可逆；**公司 j9 那一侧的记录我们删不掉**，需另行处理。
2. 保留期：`作废满 [30] 天` + 保存。写进 `.env` 的 `PURGE_AFTER_DAYS`（走 `MODEL_THINKING` 那条已验证的
   单行写入路径，重启后还在，`.env.example` 补一行）。钳在 1–3650，非法值 400 并说明接受的范围。
3. 一个搜索框：按主单号 / 分单号 / stem 过滤候选。**它只过滤，不放宽**——搜一个没作废过的票，
   回一句"这张票还没作废，先在台账里作废它"，而不是把它列进来。
4. 候选列表，每行一张票 + 勾选框，默认全选：
   `类型徽标 · 主单号 · 分单号 · 作废人 · 作废时刻 · 是否在提交台账（=回传过公司）· 本机占用`
   「是否在提交台账」这一列必须显示：要抹的是有证据的那批，得让人看清再点。
5. 底部「全选 / 全不选」+「删除选中的 n 张」，两步确认（第二颗变「确认删除这 n 张」）。
6. 执行结果逐张报成败（照抄提交那圈的做法：一批里有一张卡住不许其余的假报已删）。

## 3. 「删干净」的落点清单

分单（按 stem，先过 `store.safe_stem`）：

| 位置 | 处理 |
|---|---|
| `input/<source_name>` | 删（上传的原件；留着监控目录还会再捞一遍）。`source_name` 取自 qc 记录、**当年是用户传上来的文件名**，所以它和 stem 一样要过 `safe_stem` 那套单段校验才敢拼路径——不能因为它"是我们自己写进去的"就省了 |
| `output/archive/<stem>/` | 整个目录删（L0 原件 + `manifest.json`） |
| `output/transcript/<stem>.json` | 删（L1 逐字转录） |
| `output/raw/<stem>.json`、`output/air/<stem>.json`、`output/qc/<stem>.json` | 删（L2/L3/红旗） |
| `output/preview/<stem>.pdf` | 删（Excel 转出的预览） |
| `output/staged/<stem>.json` | 删（含模型原样快照 + 逐字段留痕） |
| `output/submitted.json[stem]` | 删这条（回传凭据转成 `purged.jsonl` 里那一行） |
| `output/voided.json["hawb|"+stem]` | 删这条 |
| `output/submit_guard/<sha1(复合键)[:16]>.json` | 删（键从台账条目里的 `key` 取，别拿号拼路径） |
| MySQL（配了 `DB_URL` 才做） | `DELETE ... WHERE source_file = ?`，复用 `db_writer` 已有的那句 |
| `output/raw/all_hawbs.json`、`output/air/all_hawbs_air.json` | **不是删文件，是调 `store.rebuild_summary()` 重建**——聚合副本里还留着这张票的全字段值 |
| `server._RENDER_CACHE` | 清掉该 stem 的所有页图条目——否则删完还能从渲染缓存里翻出票面 |

主单（按归一化主单号，先过 `store.mawb_source_dir` 那套字符校验）：`output/master/<key>.json`、
`output/mawb_source/<key>/`、`master_submitted.json[key]`、`voided.json["mawb|"+key]`，同样清渲染缓存。

**主单是共享的，这条最容易出事**：一张主单下挂着好几张分单。删分单**绝不动**主单文件；
只有作为「删这张主单」的一部分、且**提交台账里已没有任何未清除的分单引用它**时才删。
引用检查放在计划里算，不放界面。

## 4. 执行顺序（这块是设计的核心）

每张票按这个顺序做，理由写在右边：

```
1) 计划   纯函数算出这张票要动哪些路径 + 凭据行内容        ← 可单测，不碰磁盘
2) 凭据   先往 purged.jsonl 追加一行（含文件清单快照）      ← 崩溃了就还能看出来在删谁
3) 文件   逐个 unlink / rmtree，每个都先过 safe_stem 校验    ← 清不干净也绝不越界
4) 台账   删 submitted.json / voided.json 里的条目
5) 聚合   rebuild_summary() + 清渲染缓存
```

先写凭据再删文件：反过来（先删台账条目）会让这张票**失去索引而文件还留在盘上**，
成为没人能找到的孤儿数据。第 4 步放在第 3 步之后，半途失败时台账条目还在，票还能被重新挑出来删——
**整个操作按幂等设计：跑两遍的结果与跑一遍一样，第二遍是无操作而不是报错。**

越界防护：所有路径只由 `stem` / 归一化主单号拼出，两者都要过已有的校验
（`store.safe_stem` 挡 `/`、`\`、`..`、空名；`store._MAWB_DIR_RE` 只认 `[0-9A-Z]{6,20}`）。
删除清单里任何一条解析到根目录之外，整张票作废不做。

## 5. 服务端

- `GET  /purge/candidates?days=30` → `{days, items:[{kind,key,stem,mawb,hawb,void_by,void_at,in_ledger,bytes}], total_bytes}`
  只读，供面板与徽标。徽标只要条数，所以条数那条路径不算 `bytes`（`stat` 归档目录比读两份 JSON 贵）。
  这里的 `days` **只是假设预览**（"保留期若改成 7 天会捞出哪些"），它不授权任何删除。
- `POST /purge` 体 `{items:[{kind,key}]}` → 逐张 `{ok, key, removed:[...], error}`。
  **保留期只认服务端存的 `PURGE_AFTER_DAYS`，不收请求里带的天数**：否则传一个 `days=0` 就能删掉刚作废的票，
  整个保留期成了摆设（这条是自检时抓出来的）。服务端按那个值重新算一遍候选，拒绝任何不在候选里的项——
  前端的勾选框不是授权，重算才是。这样构造请求也没法删一张没作废过的票或别人的票。
- `GET /purge/config` 读保留期，`POST /purge/config` 写保留期。写完不影响正在算的那一次。
- 三个口全部 `require_admin`，与 `/stats`、`/stats/export` 同一道门。
- `purged.jsonl` 一行内容：`{at, by, kind, key, stem, mawb, hawb, submitted_at, receipt_action, days, files, auto:false}`。
  `days` 记下当时生效的保留期（事后要能回答"那批是按 30 天还是 90 天清的"）。
  `files` 存文件名列表不存内容——想知道删了哪几个文件，不想知道票上写了什么。

## 6. 测试策略（先红后绿，每条做变异验证）

- **计划函数（纯，主力）**：给定 voided/submitted/master 三份状态，输出的路径清单精确等于预期；
  未作废 → 空；作废但未满 N 天 → 空；满 N 天 → 全清单；两次运行第二次为空（幂等）。
- **越界**：stem 带 `..` / `/` / `\` / 空、主单号带非法字符 → 拒绝且不产生任何删除动作。
- **主单共享**：同主单下还有一张未清除的分单 → 主单文件不出现在清单；最后一张清了 → 出现。
- **副本与缓存**：删完 `all_hawbs*.json` 里不含该票；渲染缓存里该 stem 的条目被清。
- **顺序**：凭据行先落、文件后删（用一个会失败的假删除来验中途状态仍可恢复）。
- **门禁**：非管理员读/写三个口一律 403，未登录 401。
- **拒绝名单外**：提交的 item 不在候选里（未作废 / 没满期 / 不存在）→ 该项 `ok:false` 带原因，且不动磁盘。
- **保留期不收客户端的**：`POST /purge` 体里带 `days:0` 也不许删刚作废的票——服务端只认 `.env` 里那个值。
- **保留期**：写 `.env` 单行、钳位、非法值 400；`.env.example` 有这一项。
- **前端**：静态断言（候选渲染、两步确认第一次不发请求、公司侧那句常驻、徽标、搜索只过滤不放宽、
  内联样式与色值两条老守卫）。

## 7. 明确不做

- 不做进程内定时器（用户已同意"按钮 + 徽标"这一档）。要自动再说，且自动跑的那次会在凭据里标 `auto:true`。
- 不碰 `_quarantine_20260920/` 那批退役件（不是"一张票"，是仓库清理，另一件事）。
- 不删浏览器里的 localStorage 草稿：那在各人机器上，服务端删不到；面板说明里写一句"本人需自行清草稿"。
- 不做"删除未作废的票"。要删就先作废——保留这条单一不变式，比多给一个口子值钱。
