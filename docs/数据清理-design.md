# 数据清理（安静满 N 天的票自动删干净）· 设计

日期：2026-10-11（v1.14.0 初版）／同日晚上改判据（v1.15.0）
状态：两版都已实现。v1.14.0 端到端验过（回归 501 绿、23 条变异逐条杀回、隔离环境浏览器走通）；
v1.15.0 见 §0 与文末的验证记录。

## 0. v1.14.0 → v1.15.0：判据换了，这一版推翻的是自己那条不变式

v1.14.0 写死的口径是「候选只有**已作废且满 N 天**的票」。这条现在**作废**，理由不是它不安全，而是它把
功能实现错了方向：**为「别让我手工清理」设计的东西，被做成了"要先由人做一次判断"**。制单员不点作废，
票就永远留在服务器上越积越多——要省的那个维护动作原样回来了，只是从"删"挪到了"先得有人作废"。

所以准入条件从「谁点过什么」挪到「数据在盘上躺了多久」：

| | v1.14.0 | v1.15.0 |
|---|---|---|
| 进名单 | 已作废 且 作废满 N 天 | 最后一次被碰之后安静满 N 天 |
| 作废的角色 | 准入条件 | 名单行上的一个标记（信息） |
| 谁执行 | 只有管理员在面板上点 | systemd timer 每天一轮 + 面板"要提前删才勾" |
| 默认勾选 | 全选 | 一张都不勾 |

自动那一档**绝不伪造作废戳**：不写 `voided.json`，凭据里 `auto:true`、`by:"auto"`，`who` 留空。
事后翻这本要能分清"日子到了自己走的"和"某个管理员挑出来按下去的"。

新增的口子（本轮交付，装不装由人点头）：`run_purge.py`（不带 `--auto` 只列名单，什么都不删也不写状态）、
`deploy/hawb-purge.{service,timer}`（**文件跟着部署走，脚本一行都不 enable/start**）、
`output/purge_last_run.json`（面板顶上那句「上次自动清理」读它）。

## 1. 要解决的问题

台账与统计里积着测试票与历史票。v1.11.0 的「作废」是软闸门——只把行从台账与正确率里收起来，
**票面原件与全部解析产物还在服务器上**。用户这三句是这一版的需求原文：

- 「如果制单员不点作废那么数据会一直存在服务器里越积越多，管理员要有权限把制单员的所有数据定期清理掉」
- 「每一票运单存够多少天就自动删除掉，不需要人为维护」
- 「时间我要自定义，不要写死」

口径（逐条都有用例钉着）：

- **判据 = 安静满 N 天。** 一张分单的最后被碰时刻取这三处里最晚的：`output/qc/<stem>.json` 的
  `processed_at`（解析）、`output/staged/<stem>.json` 里最后一次人动它（`events` 末条、`staged_at`、
  `submitted_at`）、`output/archive/<stem>/` 的目录 mtime（原件后来被换过也看得到）。
  主单同理：`output/master/<key>.json` 与 `output/mawb_source/<key>/` 的 mtime，加上主单台账里那次提交时间。
  **只看一处会多删**：一张上周刚被复核并暂存过的票，`processed_at` 可能还停在四十天前那次解析上。
- **时间读不出来一律当"没满"。** 判据错了只可能是"少删几张"，绝不可能是"多删"。
- **一个旋钮**：还是 `.env` 的 `PURGE_AFTER_DAYS`（钳 1–3650，非法值 400 并说明范围）。面板那颗输入框
  只是换了语义（`作废满 [30] 天` → `安静满 [30] 天`）。执行路径**只读服务端那一份，永远不看请求里带的天数**。
- **硬删 + 一行删除凭据**（`output/purged.jsonl`，只追加，新建那一次就收 600——这本里有作废物与操作人两类名字）。
  凭据与名册都**只放号、时间与文件名，一格都不许出现票面内容**。
- **仅管理员**（面板）。门禁落在服务端 `require_admin`，顶栏按钮 `hidden` 只是配套，不是防线。
  `run_purge.py` 不经 HTTP，它由 systemd 以文件属主身份跑。
- 磁盘不是瓶颈（生产实测 37 票共 17 MB）。这个天数决定的是**"公司回头对账／出事追认时还查得到多久的票"**
  那个窗口，值由人自己填。

## 2. 入口与界面

独立的浮层「数据清理」，与「统计」「账号管理」同一套壳（`.gate` + `.card`），顶栏一颗仅管理员可见的入口，
上面挂名册条数徽标（「清理 3」）。

**为什么不开在统计窗口里**：统计顶部那对日期框是"算哪些票"的分析窗口，安静期是"躺够多久就抹掉"——
两个含义不同的时间轴并排摆，就会出"改了安静期怎么统计行数也变了"这类误判（同上传/解析时间混淆一族）。

面板内容（v1.15.0 的语义：**这是自动清理的名册，不是"挑哪些已作废的能删"**）：

1. 顶部第一行是**「上次自动清理：时间 · 查了几张 · 删了几张 · 有没有失败」**。定时器是另一个进程，
   web 进程既不知道它跑没跑、也不知道它失败过；不写这句就是静默失败（systemd 日志不是管理员会翻的地方）。
   没有状态文件要说「从没跑过」，不能留一个空日期看着像跑过。
2. 常驻一句说明（不是一次性 toast）：删除不可逆；勾选只用于"想提前删某几张"，默认一张都不勾；
   **公司 j9 那一侧的记录我们删不掉**，需另行处理。
3. 安静期：`安静满 [30] 天` + 保存 → `.env` 的 `PURGE_AFTER_DAYS`（走 `MODEL_THINKING` 那条已验证的单行写入
   路径，重启后还在）。被拒的数字不留在框里——那是"现在满几天"的当前值。
4. 搜索框：按主单号 / 分单号 / 票名过滤名册。**只过滤，不放宽**——没满安静期的号搜不出来的。
5. 名册每行一张票 + 勾选框，**默认全不选**（不可逆操作不该"开门就全选、点两下抹光"）：
   `类型徽标 · 票名 · 主单号 · 分单号 · 安静了多久 / 作废标记 · 是否回传 · 本机占用`
   第一格答的是**"这张为什么在这儿"**（安静 N 天 + 悬停给最后被碰时刻），作废只作第二行的标记，
   没人点过作废要如实写「没人点过作废」；「是否回传」这一列必须显示——要抹的是有证据的那批。
6. 空名单不能是一句"没有票"：要说清是**"没有躺够日子的票"**，并给出下一步（等，还是把安静期改短）。
7. 底部「全选 / 全不选」+「删除选中的 n 张」，两步确认（第二颗变「确认删除这 n 张」）。
8. 执行结果逐张报成败：一批里有一张卡住不许其余的假报已删（照抄提交那圈的做法）。

## 3. 「删干净」的落点清单

分单（按 stem，先过 `store.safe_stem`）：

| 位置 | 处理 |
|---|---|
| `input/<source_name>` | 删（上传的原件；留着监控目录还会再捞一遍）。`source_name` 取自 qc 记录、**当年是用户传上来的文件名**，所以它和 stem 一样要过 `safe_stem` 那套单段校验才敢拼路径——不能因为它"是我们自己写进去的"就省了 |
| `output/archive/<stem>/` | 整个目录删（L0 原件 + `manifest.json`） |
| `output/transcript/<stem>.json` | 删（L1 逐字转录） |
| `output/raw/<stem>.json`、`output/air/<stem>.json`、`output/qc/<stem>.json` | 删（L2/L3/红旗） |
| `output/preview/<stem>.pdf` | 删（Excel 转出的预览） |
| `output/staged/<stem>.json` | 删（含模型原样快照 + 逐字段留痕） |
| `output/submitted.json[stem]` | 删这条（回传凭据转成 `purged.jsonl` 里那一行） |
| `output/voided.json["hawb|"+stem]` | 删这条（票都没了，留着是个悬空键） |
| `output/submit_guard/<sha1(复合键)[:16]>.json` | 删（键从台账条目里的 `key` 取，别拿号拼路径） |
| MySQL（配了 `DB_URL` 才做） | `DELETE ... WHERE source_file = ?`，复用 `db_writer` 已有的那句 |
| `output/raw/all_hawbs.json`、`output/air/all_hawbs_air.json` | **不是删文件，是调 `store.rebuild_summary()` 重建**——聚合副本里还留着这张票的全字段值 |
| `server._RENDER_CACHE` | 清掉该 stem 的所有页图条目——否则删完还能从渲染缓存里翻出票面 |

主单（按归一化主单号，先过 `store.mawb_source_dir` 那套字符校验）：`output/master/<key>.json`、
`output/mawb_source/<key>/`、`master_submitted.json[key]`、`voided.json["mawb|"+key]`，同样清渲染缓存。

**判据换成"安静了多久"之后多出来的一条硬要求**：计划里那张清单分三段，而**三处时间来源排在最后删，
名册的扫描键（分单的 `qc`、主单的 `master/<key>.json`）排在最后一个**。中途任何一步失败，这张票要么还在
qc 上、要么还在 staged/归档目录上，下一轮照样能在名册里看到它、把半截删完。反过来（qc 先没了、后面还剩个
preview），它的安静时间再也算不出来 → 判"没满" → 那半截文件成了没人来找的孤儿数据——和"先删台账条目"
是同一个坑，这回到了"时间"上。

`input/` 那一格是**按 qc 记录里的 `source_name` 找的**：qc 已经不在了（被手工删过、或上一次删到一半），
这一格就找不到，上传原件会留在盘上。已知边界，不做兜底 glob——`purged.jsonl` 里那行的文件清单能
回答"这次删了哪几个"，对不上就说明这一格本来就没在计划里。

**主单是共享的，这条最容易出事**：一张主单下挂着好几张分单。删分单**绝不动**主单文件；
只有作为「删这张主单」的一部分、且**提交台账里已没有任何未清除的分单引用它**时才删。
引用检查放在计划里算，不放界面。自动那一路同理：兄弟票删完，主单在**下一轮**才自己进名册。

## 4. 执行顺序（人工与自动两条共用同一个 `remove()`）

```
1) 计划   纯函数算出这张票安静到没满、要动哪些路径 + 凭据行内容   ← 可单测，不碰磁盘
2) 凭据   先往 purged.jsonl 追加一行（含文件清单快照）          ← 崩溃了就还能看出来在删谁
3) 文件   一段一段删：派生物 → （没出错才）归档目录 + 安静时间来源  ← 一段失败就不走下一段
4) 台账   删 submitted.json / voided.json 里的条目              ← 只有全删干净才动
5) 聚合   rebuild_summary() + 清渲染缓存
```

先写凭据再删文件；台账条目最后动。半途失败时台账与三处来源都还在，票会被重新挑出来——
**整个操作按幂等设计：跑两遍与跑一遍结果一样，第二遍是无操作而不是报错。**

越界防护：所有路径只由 `stem` / 归一化主单号拼出，两者都要过已有的校验
（`store.safe_stem` 挡 `/`、`\`、`..`、空名**与超过 120 字的名字**——上传那一步本来就限 120，
更长的不是这台系统写出来的；`store._MAWB_DIR_RE` 只认 `[0-9A-Z]{6,20}`）。
**长度这一格是 VM 上补的**：Linux 单段文件名上限 255 字节，一个 300 字的 stem 会让 `stat`
直接抛 `ENAMETOOLONG`，而 Windows 的 `is_file()` 对同一条只回 `False`——本机 524 条全绿、
推到 VM 上第一次跑就炸（见 §8）。清理这一路的读盘一律"读不出＝不在盘上"，不许因为一个路径
stat 不动就把整次删除崩掉。

## 5. 服务端与入口

- `GET /purge/candidates?days=&brief=` → `{days, preview_days, items:[{kind,key,stem,mawb,hawb,quiet_at,
  idle_days,voided,void_by,void_at,in_ledger,bytes}], total_bytes, last_run}`。只读，供面板与徽标共用一份数据。
  徽标那条路径不算 `bytes`（`stat` 归档目录比读两份 JSON 贵）。`days` **只是假设预览**（"若改成 7 天会捞出哪些"），
  它不授权任何删除；接口**不把绝对路径与删除计划交给浏览器**（`files/dirs/sources/drop` 一律剥掉）。
- `POST /purge` 体 `{items:[{kind,key}]}` → 逐张 `{ok, key, removed, error}`。
  **安静期只认 `.env` 里那一份，不收请求里带的天数**：否则传 `days=0` 就能删掉昨天刚碰过的票，安静期成了摆设。
  服务端按那个值重新算一遍，不在名册里的项由 `refuse()` 逐张报原因（"还没安静满 30 天：最后一次被碰是…"），
  且一个字节都不动。前端的勾选框不是授权，重算才是。
- `GET/POST /purge/config` 读写安静期（同一份，只有这一处存）。
- 三个口全部 `require_admin`，与 `/stats`、`/stats/export` 同一道门。
- `run_purge.py [--dry-run|--auto]`：算名册 → 逐张删 → 逐张报成败 → 写 `output/purge_last_run.json` →
  退出码（全成 0，有失败非 0）。**不带 `--auto` 什么都不删、连"跑过"都不写**。这是给人先看名单的那一步，
  也是整个自动化唯一的刹车。名册空着也盖时间戳（否则分不清"定时器没跑"与"跑了但没到期"——两个处理动作相反）。
- `purged.jsonl` 一行：`{at, kind, key, stem, mawb, hawb, days, quiet_at, idle_days, voided, void_by, void_at,
  submitted_at, receipt_action, in_ledger, auto, by, who, files}`。自动档 `auto:true / by:"auto" / who:""`；
  人工档 `auto:false / by==who==登录名`。`days` 记下当时生效的安静期（事后要能回答"那批按 30 天还是 90 天清的"）。
- **不挂进程内定时器**：`hawb-desk` 是 `Restart=always`，进程内起循环等于每次重启就把计时器重置一遍，
  而失败只躺在日志里。自动那一路走 systemd timer（`deploy/hawb-purge.timer`，`OnCalendar=*-*-* 04:10:00`、
  `Persistent=true` 关机错过一夜开机补跑）。装它 = 改这台共用机的系统配置，**要用户明确点头**，
  `sync.sh` / `release.sh` 里一条 enable 都不许出现。

## 6. 测试策略（先红后绿，每条做变异验证）

- **判据**：没作废但安静满 N 天 → 在名册；昨天刚被碰 → 不在；三处来源取最晚（复核/暂存过就不算安静）；
  时间读不出 → 永不满期；安静天数与作废标记都在行上。
- **删序**：三处时间来源排在最后、qc 最后一个动；中途一张失败时这张**下一轮还在名册上**（半截能被收走）。
- **凭据**：自动档标 `auto/by/who` 且不写 `voided.json`；人工档留住登录名；名册与凭据都不带票面内容。
- **入口**：dry-run 点名每张占多少字节、一个字节都不删、不写状态；`--auto` 清空名册、逐张报、状态里
  `checked/removed/failed/errors` 对得上；有失败退非 0；空名册也盖时间戳。
- **主单**：名下还有已提交分单 → 不进名册；兄弟票删完 → 下一轮自己进名册；再一轮才被收走。
- **越界**：stem / 主单号带 `..`、`/`、`\`、空、非法字符 → 拒绝且不产生任何删除动作（含藏在 `voided.json`
  里的恶意键）。
- **共享与副本**：删完 `all_hawbs*.json` 不含该票；渲染缓存该 stem 被清；主单文件在兄弟票还在时不动。
- **门禁**：三个口非管理员 403、未登录 401；`POST /purge` 带 `days:0` 也不许删刚被碰过的票。
- **前端（静态断言 + 真浏览器）**：默认不勾（`=== true`，且禁掉 `!== false` 那写法）；空态说"没躺够日子"；
  「上次自动清理」的位置 + `PURGE.run` 接的是 `j.last_run`；行上有安静天数；两步确认第一下不发请求；
  公司侧那句常驻；色值只在 tokens.css、内联 style 只放行运行时那两种、`[hidden]` 有 CSS 兜底、
  toast 第二参是样式表里真存在的类别。

## 7. 明确不做

- 不做"只删测试票"这种特例判据。判据只有一个：安静满 N 天。
- 自动那一档不伪造作废戳、不动 `submitted.json` 之外的公司侧记录（j9 那边删不掉，那是另一条流程）。
- 不碰 `_quarantine_20260920/` 那批退役件（不是"一张票"，是仓库清理，另一件事）。
- 不删浏览器里的 localStorage 草稿：那在各人机器上，服务端删不到。
- 不在 web 进程里起定时器（见 §5）。timer 文件备好但**不自动装**。
- 不做"提前删某几张"之外的手工口子：面板上勾选是唯一的手工路径，且它也只是把这张票按现值交给 `remove()`。

## 8. 验证记录

- v1.14.0：回归 501 绿；23 条变异第一轮存活 6 条，逐条补实断言后全部杀回；隔离环境（8032 起的 mock 站）
  浏览器走通；已发版上线（efreight-vm，`/health` 与静态资源逐条核对）。
- v1.15.0：本机全量 **524 绿**；26 条变异第一轮活着 4 条（主单少算一处时间来源、自动档 `by` 的等价变异、
  删完不清作废戳、空态那句断言扫的是整个函数），逐条补实后全部杀回；隔离世界（仓库外落盘 + 独立账号 +
  mock + 8032）真浏览器走通——**两条只有浏览器点得出来**：作废那一格在 132px 里被省略号截掉，
  「几张没删掉」那支红被 `.purge-run b` 顶掉成了一行黑字。
- v1.15.1：**VM 回归抓出来的平台差异**。同一条"x"*300 的用例在本机绿、在 Linux 上 `stat` 抛
  `ENAMETOOLONG` 把整轮炸成 ERROR（本机 `is_file()` 只回 `False`）。补了 `safe_stem` 的长度上限 +
  `_json` 把"读不出的路径"当成"不在盘上"。这条变异（把 try 的范围缩回原样）**本机验不出**，
  只有 VM 回归咬得住——"两台机器各记各的账"也包括各抛各的异常。
