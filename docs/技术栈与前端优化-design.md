## 0. 背景与范围

主体功能（分单 40 列 / 主单 36 列解析核对、回传 j9、审核台）已完成并在用。本轮不改任何业务口径，只做四件事：**不再把公司数据写坏 → 并发与超时收敛 → 前端重做承载与交互 → 结构收敛**。

- 不动登录/口令/公网暴露策略（D2）；不上真证书、不加 IP 白名单。

## 1. P0 · 不再把公司数据写坏

### 1.1 预读失败即拒（最高优先）

现状：`company_api.submit_order:154`、`submit_master:183` 在读不到公司当前行时把 `existing` 当空 dict 继续发。j9 两个写接口都是**整表写回**（文档：本次没给值的列写 NULL），于是"没读到"= "把这一行其余列清空"。

改法：
- 新增 `CompanyPreReadFailed(company_api)`；live 模式下预读抛异常/超时/返回空 data 且本地台账认为该行**本应存在**时 → 抛该异常，路由转 502，**一个写请求都不发**。
- "公司确实没有这一行"（首次录入，`action=insert`）仍是合法路径：以"本地台账无该复合键 + 读回空"区分于"读失败"。
- 界面文案：`没读到公司当前值，先不要提交（公司接口无响应或超时）`。

验收：故意把 `_j9_post` 的读调用打桩成超时 → 断言 502 且 `sent` 里没有任何 `*2` 写请求；断言本地台账未被写入。

### 1.2 提交幂等锁

- 键：`(归一化主单|归一化分单)`（主单侧为 `MAWB|—`）+ **提交体指纹**（对将发送的 record 做 sha256）。
- 介质：跨进程文件锁 `output/.locks/submit-<key>.lock`（与现有 `_LEDGER_LOCK` 同目录族，Windows 上退化为进程内锁 + 文档说明）。
- 语义：锁期内同指纹的重复请求 → 直接回上一次回执（`mode/idempotent:true`），不再发写请求；**不同指纹**的重复请求视为"真的要改"，放行但仍串行。锁 TTL 90s。
- 双击、代理重试、两台机器同点同一票，都不再产生第二次整表写回。

### 1.3 分单提交以服务端为准

- `/submit` 收到每张票后，服务端用 `air_reviewed` 当前值重跑 `validate_raw` + `validate_air` + `build_qc` + `verify_fidelity`（与 `master_pipeline.master_flags` 同构，函数落 `jobs.py` 供两边共用，避免又长出一套）。
- `acked_flags`：仍允许人工放行，但只在"红旗原文与本次重算结果逐条相等 **且** 该列值自上次确认后未再改动"时生效；改动过的列其红旗自动重新生效。
- `reviewer` 一律取会话身份，前端传什么都不认。
- 错误结构与主单同构：400 + `{"message","flags"}`，前端据此渲染逐条「确认无误」。

### 1.4 提交留痕可信

分单台账补：`edited_fields`、`sent_fingerprint`、`company_action`、`before`（预读到的原行，与主单侧对齐）。主单台账已有 `before`，补 `sent_fingerprint`。今日台账页（§3.4）读这两张表。

## 2. P1 · 并发、超时、内存、可观测

### 2.1 解析队列（进程内）

- `/extract` 改为**入队即返回 202** `{job_id, position}`；新增 `GET /job/{job_id}` 返回 `queued|running|done|failed` + 结果摘要；前端轮询（复用主单解析那套 `mvPoll` 的模式）。
- 闸口：`asyncio.Semaphore(DESK_CONCURRENCY)`，默认 **2**（依据：8 人 × 30 单/人/天 ≈ 每分钟 1 张，2 个槽位含 LibreOffice + 渲染尖峰已足够；超出即说明模型或公司在抖，此时排队可见正是需要的信号）。
- 队列上限 `DESK_QUEUE_MAX=200`，超出返回 429 并提示"稍后再传"。
- **已知代价（用户接受）**：服务重启会丢掉"排队中/解析中"的票；已落盘的 `output/*` 不受影响。前端对 404 的 job 自动重新入队一次，并在票行上写明"服务重启过，已自动重传"。

### 2.2 超时与退避

| 调用 | 现在 | 改为 |
|---|---|---|
| VLM chat | timeout 600s、重试 3 次 `sleep(3)` 平铺 | timeout 240s、退避 `2/8/20s ± jitter`，单票最坏 ~15 分钟 |
| nginx | `proxy_read_timeout 900s` | 与后端对齐 300s；长请求改由 §2.1 队列承担，不再有长 HTTP |
| j9 读/写 | `urlopen(timeout=30)`，零重试 | 读 10s / 写 20s，429/5xx 退避重试 2 次，全局令牌桶 **8 req/s**（文档 10/s 留余量），429 单独报错不再吞成"回传失败" |

### 2.3 内存尖峰

`vlm_extract` 逐页渲染改为生成器 + 用完即 `close`，不再把全部页 base64 攒在一个 list；`soffice` 转换由闸口串行；`IMAGE_LONG_EDGE` 给默认降采样（长边 2200）。撞 cgroup 上限的后果（整服务 SIGKILL）由这三条 + 闸口 2 共同压住。

### 2.4 日志与版本

- 统一 logger `hawb.desk`（现有 4 条 warning 扩到：登录、上传入队、解析完成/失败、提交、公司回执），每行带 `who / stem / 号 / 耗时 / 结果`。
- `/health` 增：`version+commit`、`active`、`queued`、`last_error`；部署完一眼确认服务器跑的是哪一版（不再只靠 `stale_files` 猜）。

## 3. P2 · 前端：B3 + 窄轨，零构建拆文件

### 3.1 承载

`web/index.html` 只做骨架，拆出 `web/css/tokens.css`、`web/css/desk.css`、`web/js/*.js`（状态、渲染、网络、各面板）。静态文件由 **FastAPI `StaticFiles` 挂在 `/web`**（应用自己的路由，不动 nginx 配置），页面仍走现有 `/` 路由并保留 `Cache-Control: no-store`；拆出去的 css/js 用 **`?v=<版本戳>` 查询串**做缓存击穿（版本戳来自 §2.4 的 commit 版本，页面渲染时注入），避免升级后浏览器拿旧壳——不做构建期的哈希改名，那是为了零构建这条底线让步后的取舍。部署方式不变（推文件 + 重启），**不引入构建步骤**。

### 3.2 设计令牌（先把语言立起来）

`:root` 从 5 个颜色扩成成体系的令牌：`--c-bg/--c-surface/--c-line/--c-text-{1,2,3}`、语义色 `--c-ok/--c-warn/--c-bad/--c-info`（各带 `-bg` 变体）、间距 `--s-1..--s-6`（4/8/12/16/24/32）、字号 `--f-{xs,sm,md,lg}`、圆角/阴影/层级 `--z-{sticky,drawer,toast}`。现存的 50+ 硬编码色与 24 处内联 style 全部归口到令牌；对比度按 WCAG AA 修（`--c-text-3` 从 ≈2.6:1 提到 ≥4.5:1）。

### 3.3 视图与状态机

- **核对工作台**：左 48px 窄轨（每票一个状态点 + 今天进度 `4/12`，点一下展开成覆盖式列表）｜中半屏票面（常驻，支持缩放/新标签/下载/点字段定位）｜右半屏"待办清单"：置顶待办条（红旗 N · 漏取 N · 已改 N）+ 分组手风琴字段 + 底部常驻操作条（提交 / 导出 / 上一票 / 下一票）。
- **今日台账**（整页）：一张表 = 今天经手的票，列含 `单号 / 主单 / 状态 / 红旗 / 排队位次 / 本台提交（谁·何时） / 公司发送状态 / 原件 / 打开`。数据源 §1.4 的台账 + 公司状态（按主单聚合查，带令牌桶）。这一页也是"两台机器各记各账"事实的展示位。
- **主单检索**：顶栏抽屉；结果并入同一个核对壳（列面 36、提交口不同），不再有两套渲染分支。
- 状态集中到一个 `store`（普通对象 + 订阅），渲染从"23 处 innerHTML 全量重建"改为**分区局部更新**；轮询收进一个带退避、页面隐藏即暂停（`visibilitychange`）、有最大次数的调度器。

### 3.4 必须修掉的交互缺陷

1. **主单 36 列的编辑与红旗确认现在完全不进 localStorage**，刷新即丢 → 与分单同一套草稿机制（键含票类型）。
2. 可点的非元素（票行、字段名、chip、还原）全部改成真正的 `<button>`，补 `aria-*`、`label for=`、可见 focus 描边（现在 `textarea:focus{outline:none}`）、触屏目标 ≥28px（现在 `.btn.sm` 22px、`.ackb` 19px）。
3. 状态不再只靠色点区分（色 + 文字 + 图标）。
4. `u.role` 等未转义插值统一走 `esc()`；`esc()` 补单引号。
5. 错误提示不再互相覆盖：toast 改队列，且失败要留在票行上可回看。
6. 角色标签：录入员不再被显示成"制单员"（服务端权限仍是同权，D2 未动）。

### 3.5 前端测试

拆文件顺带把**纯逻辑**（状态归约、草稿合并、红旗过滤 `effectiveFlags`、单号归一、状态文案映射）从 DOM 里剥出来放 `web/js/logic.js`，测试用开发机已有的 Node 直接 import 这个文件断言输入输出——不引 jsdom、不引测试框架（Python 侧 `subprocess` 调 `node --input-type=module -e …` 并解析退出码）。碰 DOM 的部分继续用现有两招兜：静态扫描（挂载前缀、未转义插值、`on*=` 内联事件、缺 `label`/`aria` 的控件）+ 服务器真实浏览器手工走查清单。

## 4. P3 · 结构收敛

1. **先搬后删**：新建 `codes.py`（IATA/国家码表、`TEL_COUNTRY_CODES`、`_iata_place`、`_fmt_mawb`、`_parse_party`、`clean_tax`/`TAX_LABEL_RE` 等真正在用的公共件），`to_air/validator/fidelity/export_excel/db_writer/run_batch` 改指新处，禁止再跨模块调私有函数（下划线开头的导出一律视为违规，加一条 import 扫描测试）。
2. **删退役规则层**：`hawb2json.py` 剩下的部分（规则解析 CLI `convert_file/project_raw/project_air/validate/main`、OCR 兜底、`.xls` 直读）整体删除；已确认没有任何 `.bat` 或文档调用该 CLI。依赖随之收轻：`pdfplumber`、`xlrd`、`rapidocr-onnxruntime`、`opencv-python`、`onnxruntime`、`numpy` 从 `requirements.txt` 摘掉（`pandas` 若只为导出留则一并评估）。删除前把这套 L3 基线 fixtures 保留（它们仍是回归资产）。
3. **单一真源**：字段契约只在一处（`schema.py` 生成 → `FIELDS`、`CN_HEADERS`、`schema.sql` 列、前端列面都从它取或从 `/api/schema` 取），撤掉现在用来防漂移的比对测试的必要性（不是删测试，是让它变成"生成物一致性"检查）。主单侧 `MASTER_FIELDS` 同样并入。
4. **两条链合并**：`store._write` / `auth._write` / `master_pipeline._write` / `config.persist_model_choice` 合成一个 `atomic_write(path, data, mode=0o600)`；短/长字段拆分与 `_missed_flags` 那类重复实现各留一份；`MASTER_COLS = mf.MASTER_COLS` 这类别名删掉。
5. **并发安全**：`store.rebuild_summary` 的非原子写、`archive_original` 的 `manifest.json` 非原子写改走 `atomic_write`；台账跨进程写加文件锁（Windows 降级说明）。
6. **配置面**：`config.py` 的环境变量收成一张表（名字/用途/必填条件/默认），`.env.example` 补齐现在缺的 10 项，删掉没人读的 `BLSC_API_KEY`；`set_model`/`set_master_model` 不再改模块级全局（改为读函数），消掉"快照与 os.getenv 两套真值"。
7. **清死码**：~~`store.master_ledger`（无人读）~~ **核实为误判，已保留**——`company_api.py:247` 的主单预读即拒就靠它判断"本机录过但公司没读到"；`master_fields.submit_body` 反过来并入生产路径（`company_api` 组 `AMS_RECORD` 时调它），"恰好 36 列"这条规则从此只有一处。`.gitignore` 里指向不存在目录的条目与"39 字段"这类过期注释一并修。
