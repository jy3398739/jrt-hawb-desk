# 主单解析与回传公司（mawb2）设计

日期：2026-09-28　范围：`release/hawb_extractor`　状态：已定案，实施中

## 0. 口径来源（用户定案）

| 决定 | 内容 |
|---|---|
| 主单原文来源 | **只用公司接口返回的文本**（`AMS_RECORD` 列 + 外层资料块），不依赖本机有没有主单原件 PDF |
| 触发时机 | **检索到就自动解析**（每个新主单一次模型调用，重复检索走缓存不再花） |
| 已录入的是否过模型 | **一律过模型，路径完全统一**（`AMS_RECORD` 已有值也重跑一遍提取） |
| 防编造 | 加一段**主单口径约束**进 prompt（主单没有的栏位一律留空，不推算） |
| 字段面 | **主单是主单**：用公司 `AMS_RECORD` 36 列原样，不套我方分单 40 字段契约 |
| 提交 | **两边都要提交回公司**：主单走 `POST /api/v1/j9/mawb2/`，分单走已接通的 `hawb2` |
| 主单提交门 | **与分单同构**：红旗清零（或逐条「确认无误」留痕）+ 复核人署名 + 人工点提交，服务端重算后才发 |
| 主单↔分单一致性对比 | **本轮不做**，等规则定案 |

## 1. 两套契约，一条引擎

分单链（不动）：票面 → L1 → L2 我方 40 字段 → L3 `to_air` → 红旗 → `hawb2`。
主单链（新增）：公司资料 → L1 文本 → L2 主单 36 列 → `clean_ams` → `validate_master` → 保真回查 → `mawb2`。

复用**引擎件**：转录结构 `{lines, full_text}`、VLM 调用与重试、`verify_fidelity`、红旗收集、
提交门与台账范式。不复用字段表：主单不过 `to_air` 的 IATA 三字码归一（主单表没有航路栏），
不进 `output/air`、Excel、DB、分单提交台账。

## 2. 主单字段面 = `AMS_RECORD` 36 列

`MAWB_NO` / `GOODS_INFO_HSCODE` / `SLAC` + 发货人 11 列 + 收货人 11 列 + 通知人 11 列。
每组的 11 列：`COMP_NAME COMP_ADDRESS CITY COUNTRY STATE POSTAL TEL FAX EORI AEO EMAIL`。

列名按公司原样，两处历史拼写**不"修正"**：
- `NOTIFYE_INFO_COUNTRY` 多一个 E；
- 主单表收货人城市是单 T `CONSIGNEE_INFO_CITY`（双 T `CITTY` 只属于分单表）。

主单表**没有**：货名列、税号列、件数/毛重、始发/目的/航路、签发日期、分单号。
所以：
- 外层 7 字段（`JOB_ID MASTER_NO SHIPPER_INFO CONSIGNEE_INFO NOTIFY_INFO GOODS_NAME GOODS_DESC`）
  是**只读参考**，`GOODS_NAME/GOODS_DESC` 不进提交体；
- 票面上的 USCI/CNPJ 一类税号在主单侧**没有落点**，解析不出来也不许塞进 EORI（EORI 必须是
  两位国家字母开头的形态），出现即红旗报"主单表没有税号列"。

服务端维护三列 `HMY_ID / CREATE_TIME / SEND_STATUS`：不进 L1、不进提交体。

## 3. L1 文本拼装（`master_fields.build_transcript`）

行序：`MASTER_NO` → `AMS_RECORD` 每列一行 `列名: 值`（空列与服务端三列跳过）→ 外层资料块
（`SHIPPER_INFO/CONSIGNEE_INFO/NOTIFY_INFO/GOODS_NAME/GOODS_DESC`）各一行，非空才出行。

已录入的列排在拼接资料块**之前**：模型先看到结构化真值，才不会被"地址和电话黏在一行"的文本带偏。
资料一律逐字出行、不预切——切黏行是模型 + 清洗阶段的活，在这里切等于让保真回查自己查自己。

## 4. 解析（`vlm_extract.extract_master`）

主单专用字段表 + 前置口径段：这是航空主单资料文本、**没有图片**（视觉模型也不发票面图，
主单没有版式原件）；`PIECES/WEIGHT/ORIGIN_NAME/DEST_NAME/TO1-3/HAWB_NO/CREATE_TIME` 这类
主单侧不存在的栏位一律留空，绝不推算、绝不用发货人城市猜起运港；`NOTIFY_INFO` 段要单独取、
不许并进收货人。保真铁律沿用分单：值必须逐字来自 L1，允许的唯一改写是主单号补横杠。

## 5. 清洗（`master_fields.clean_ams`）与红旗（`validator.validate_master`）

清洗只动格式不动内容：连续空白归一、`SLAC` 转整数、EORI/AEO 去空白转大写、国家码转大写、
`MAWB_NO` 凑 `3位-横杠-8位`（位数不对原样留着交给红旗）、没值一律 `None`（整表写回=写 NULL）。

红旗作用在主单列上，三组（发货人/收货人/通知人）同规则：电话区号↔国家不一致、EORI 形态异常、
`MAWB_NO` 非 3-8 格式、`SLAC` 非整数、限长 50 的九列超长（这九列公司直接 400，提前报出来），
以及"主单表没有税号列"的落点提示。保真回查按主单列面参数化复用：L2 值必须能在 L1 逐字找到，
外加主单号/HS/EORI 反向漏抄。

## 6. 缓存与状态（`master_pipeline`）

`output/master/<归一化主单号>.json`：
`{mawb, text_md5, state: parsing|done|failed, model, elapsed, ams_raw, ams_clean, qc, error, updated_at}`。

- `text_md5` = L1 文本的 md5。命中且 `done` → 秒回，不再调模型；公司资料变了 → 重跑。
- 同一主单并发去重，不起第二个解析任务。
- 解析失败：`state=failed` + 错误原文，页面上给「重新解析」，**不退回半吊子的正则拆解**
  （`master_parse.py` 那套标签拆解随前端切换一起删除，两套口径并存迟早漂移）。

## 7. 上屏与提交

主单检索卡片点「送入主单核对」进入同一对面板：
- 左栏（票面预览位）：L1 原文，标注"公司资料文本，无票面版式，点字段不能定位"。
- 右栏（核对位）：36 列**可编辑**表格 + 红旗 chips（带「确认无误」，沿用分单按当前值动态清的口径）
  + 保真 x/y + 外层 7 字段只读参考 + 「重新解析」+「提交主单回公司」。
- 解析中：状态条轮询 `GET /master/{mawb}`，与分单一个节奏。

提交 `POST /master/submit`：门 = 红旗全清（或逐条确认留痕）+ 复核人署名；服务端**重算**
（不信前端值）后才发 `mawb2/`。公司回 400 或锁行（读到的 `SEND_STATUS` 非 0/2）→ 409/502
回显原因、**不写台账**。提交体是整表写回，所以未改的列也要带上（先读后写，与分单同一条纪律）。

主单提交台账单独一份 `output/master_submitted.json`（主单号 → 复核人/时间/回执/提交前
`AMS_RECORD` 快照）。不混进分单 `submitted.json`——那边是 stem 索引，主单没有 stem。

## 8. 测试

回归全程离线：模型客户端与公司 HTTP 层全部打桩，`tests/run_tests.py` 继续把
`COMPANY_API_MODE/URL/两把 key` 钉空，忘打桩的出网调用会立刻抛错。覆盖：字段表与两处历史拼写、
L1 行序与逐字性、清洗与 `None` 语义、主单红旗（含限长与税号落点）、`mawb2` 先读后写与锁行不发写、
缓存命中不再调模型、并发去重、提交门（未清拒 / 确认后放行 / 只人工点才发）、主单台账不污染分单台账、
前端契约（36 列可编辑 + 提交按钮 + 无 IATA 归一 + 解析中轮询）。现有 172 项不许掉。

## 9. 边界与风险

- `mawb2` 是**整表写回**：漏列=写 NULL。这是主单提交最大的不可逆面，所以提交体必须来自
  "读到的行 + 人工改动"合并，且门在人工点击。
- 每次检索一次模型调用是用户明确选的；缓存把重复检索挡住，但**看错号也会花一次**。
- 主单侧无票面版式，定位模式（点字段→票面高亮）不适用，界面上要明说而不是静默失效。
- 公司接口是公网 http 明文传 key（已在 IT 文档侧向用户提示过），主单提交沿用同一把主单 key。
