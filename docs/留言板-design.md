# 规则留言板（所有人可提，管理员定性，落成仍在代码里）· 设计

日期：2026-10-21　状态：**设计已逐节确认，未动代码**。目标版本 v1.33.0，上线方式见 §8。

## 0. 一句话与原话

> 业主 2026-10-21：「先给我上个留言板，权限所有人都可以用；我需要让录入员把他们知道的规则收集起来。」
> 采集形态定案：**自由文本为主、标签可选**；**互见、只能改自己发的、改与撤都留痕**；**四态、只有管理员能改、改都要留话**；
> **能挂当前这张票并可点开**；**只采集不讨论**；**VM 那台不做**。

要解决的问题：航空录入的规则大量长在老师傅手上（哪个国家邮编带横杠、哪格该填什么号、票面哪里印着什么），
现在这些只有一条路进系统——他们顺口说一句、业主想起来转给我。没有承接的地方，说过就等于没说过，
第二年同一件事再被提起一次。留言板要做的就是把这条口头通道变成**有署名、有时间、有结论、能倒查**的一本台账。

**它不是规则引擎**：留言不会改变任何一格的发出值。要生效必须落成代码（§6）。

## 1. 目标与非目标

目标：① 任何登录用户都能提、能看全部；② 管理员能把一条留言定性为四档之一并留下为什么；
③ 落成规则时能从代码倒查回是哪条留言促成的；④ 没开开关的那台机器（VM）彻底没有这东西。

非目标（§9 展开）：不做运行时生效、不做讨论/回复、不做通知、不做导出、不做分页与归档。

## 2. 数据形状：`output/board.json`（独立一本，不碰 `submitted.json`）

```
{ "seq": 7, "items": [ {
  "id": 1, "by": "郭健康", "role": "inputter", "at": "2026-10-21T09:12:00",
  "text": "巴西收货人邮编都印成 8 位不带横杠，公司系统那边要带",
  "tags": {"country": "BR", "column": "CONSIGNEE_INFO_POSTAL"},     // 两个都可选
  "ticket": {"stem": "HAWB-ANGB2609026G", "mawb": "074-...", "hawb": "NGB2609026G"},  // 可选，发送那一刻的快照
  "decisions": [{"status": "accepted", "note": "已进表", "ref": "polish.POSTAL",
                 "by": "admin", "at": "2026-10-22T10:04:00"}],       // 只追加；一条都没判过就是空数组
  "revised": [{"at": "...", "by": "郭健康", "text": "原来那句"}],
  "retracted": {"at": "...", "by": "郭健康"}                        // 没撤过就是 null
} ] }
```

**文件里没有 `status` 这个键**：当前判定是服务器从 `decisions` 最后一条派生的，只在响应里给
（空数组 ⇒ `open`）。存两份状态就是留了一个迟早对不上的地方。

**判定的历史不销毁**：一条留言可以先被标"已收"、后来发现做错了改回"先放一放"——两条话都留在
`decisions` 里，界面上显示最近一次判定，要翻历史就在「复制这条」的文本里全带上。

四条刻意的形状：

1. **署名与角色由会话取**，请求里写什么都不认（同 `/polish`、`/stage`）；`by`/`role` 不是入参。
2. **改与撤都不销毁原文**。本人改文本 ⇒ 旧文本进 `revised` 数组，全留不截断；撤回 ⇒ 写 `retracted`，行还在列表里（灰显）。
   "他当时提的其实是另一件事"必须查得回，否则这本台账就成了会说谎的那一份。
3. **`tags.column` 只能取 `fieldspec.desk_keys()` 里的列名**，不在就 400。列面的家在 fieldspec，
   这里不抄第四份（`actionable_columns()` 已经是"筛选而不重定义"的写法，照它）。
4. **撤回是终止动作**：`retracted` 一写，这条就不再允许 `PATCH`（要改就再发一条新的，两条都在，
   旧的那条保留当时的原话）。不这么定，"撤回后又被偷偷改成另一件事"迟早会出现，而那正是这本台账唯一值钱的东西没了。

落点：与 `voided.json` 同一个待遇——`config.BOARD_FILE`（默认 `output/board.json`，可被 env 重指），
在 `.gitignore` 的 `/output/` 里，所以**不会随部署包上线、也不会被 `sync.sh` 覆盖**。

## 3. 服务端：路由、权限矩阵、开关

| 路由 | 谁能成 | 挡下时 |
|---|---|---|
| `GET /board` | 任何登录用户（互见，无按人过滤） | 未登录 401 |
| `POST /board` | 任何登录用户 | 401；正文空/纯空白、超 2000 字、列名不在列面 → 400 |
| `PATCH /board/{id}` | 本人改 `text`；管理员改判定（追加一条 `decisions`：`status` + `note` 必填，`ref` 选填） | 改别人的 403；非管理员动判定 403（文案「状态由管理员定」）；`status` 不在四档 → 400；`note` 空或超 200 字 → 400；**这条已撤回 → 400** |
| `POST /board/{id}/retract` | 本人（管理员不替他撤） | 403；已撤回复幂等，不报错 |
| `DELETE /board/{id}` | 仅管理员，硬删 + 服务端日志一笔 | 403 |

- `PATCH` 一条路由**按角色分派能改哪几个键**，其余键直接忽略；响应回"实际生效的那一份"，前端照响应画。
- **开关**：`config.BOARD = os.getenv("BOARD", "0") == "1"`。没开的机器这五条路由一律 **404**（不是 403——
  "这台不做"要表现得像没这功能，而不是像没权限）。`/health` 加一个 `board: true/false`，
  不开页面也能看出这台开没开（同"每份拆出来的东西都要有自己的 /health 字段"那条教训）。
- 存储：一本一把 `threading.Lock`，写走 `atomic.write_json(..., mode=0o600)`；`_load` 读坏 JSON 回空表 + 日志，不炸服务。
- **挂的票是快照，不校验**：`ticket` 存发送那一刻的 `stem/mawb/hawb` 三段文本，服务端不查它还在不在——
  查不了（人随时可能删票或清账），而留言的价值恰恰是"当时看到什么"。点不开就如实说「这张票不在了」。
  对比一下：正文与列名要挡（那是判据，挡了不会错），票号不挡（那是历史，挡了会把话憋回去）。
- **硬删只留给两种情况**：误发（发错地方、含个人信息比如客户电话邮箱写进正文了）。日常"这条我不同意"
  走的是 `不采纳`，不是删。删的那一笔进服务端日志（谁删的、删的哪条 id）。
- **代码落点**：新模块 `board.py`（`store.py` 已经管着提交台账/暂存/作废/主单四本，再塞就是把它撑成第五本；
  `polish.py` 单独立模块是先例），`server.py` 只放路由与门禁。前端**不新增 js 文件**：面板逻辑进 `desk.js`
  （与其它浮层同一处），纯函数进 `logic.js`（能被 node 单测，也不必动「脚本外链三份」那份名单）。

必改的四处（少一处就红）：`config.py` 常量、`.env.example` 加 `BOARD`（`test_env_doc` 盯着）、
`tests/` 用例自带临时目录（`run_tests._machine_files` 会比对真 `output/` 清单）、
`web/js/changelog.js` 加一条。部署清单是 `git ls-files`，数据文件天然不在里面。

## 4. 界面

**入口 = 顶栏一颗「规则留言 · 待看 N」**，三角色都可见。不收进「设置」（`applyRole()` 把 `btnSet`
整颗对非管理员隐藏，desk.js:2280，收进去等于两角看不见）；不放左栏页签（那三个的语义是"我手上的票"，
这本是全局的）。顶栏 v1.17.0 那次整合收的是**管理员专属**控件，这颗不是，所以不违背那次定案。
「待看 N」取 `GET /board` 响应里的 `counts`，**前端不自己数**。

浮层复用 `.gate` 骨架 + `openGate`/`closeTopGate`/`GATE_BACK`（Esc 与焦点归还自动生效；那条守卫从
desk.js 捞浮层名单，加 id 就进射程，不手抄元素）。

- 上半＝发一条：正文文本框为主，下面三个可选项——国家（自由填不校验）、哪一列（下拉取列面）、☑ 挂当前这张票。
- 下半＝列表：`谁 · 时间 · 正文 · 标签 chips · 挂的票（点开走 openHouse，票没了就说没了）· 四档徽章 ·
  最近一次判定的那句话与谁在什么时候定的 · 「改过／撤回于」灰字`，每条一颗「复制这条」（§6）。
- 筛选一排：全部 / 待看 / 已收 / 不采纳 / 先放一放 / 我发的，计数常驻在按钮上。
  **计数与筛选同一个判据**（照 `statsSeg`/`statsCounts`/`statsFilter` 那三个纯函数的形状，互斥且穷尽由用例钉）。
  口径写死：`待看` = 派生状态为 open 且未撤回；**所有计数都不计已撤回的行**，但「全部」那一档的列表里
  它们仍在（灰显、排最后）——计数要说的是"要你处理的有几条"，不是"这本里有几行"，两者差多少就写多少，不藏。
- 非管理员看不到「改状态」那颗，但服务端一样挡（置灰不是权限）。
- 空态分三种说清：这台没开留言板 / 开了没人提过 / 你筛的那档这阵子没有。

## 5. 错误、并发、容量、与自动清理的关系

400/403/404 的判据全在服务端（见 §3 表）；前端不做乐观更新。长度上限 2000 字是**自己定的**，
注释里写明它不是从列面或别处推出来的（免得以后有人以为改列面会改到它）。

并发：两线程同时 `PATCH` 不许丢行（用例真起两个线程）。容量：只增不删，一条约 1KB，年级别几百 KB，
**不做分页也不做归档**，注释写"到几千条再说"——不提前造。

**要紧的一条**：`run_purge` 的射程是票的落点（archive/air/qc/staged/master…）。`board.json` 必须不在它的候选
集合里，并且要写成守卫（跑一轮到期清理后 `board.json` 原样还在）。理由是同族那条教训——多个入口共用
一个算出来的集合时，新加的文件不钉一次，就等着哪天被顺手删光，而且删得很像"正常工作"。

## 6. 闭环：谁落成、"已收"到底怎么算

> **已收 = 这条已经进了代码**（`polish.py` 的表 / `codes.py` 的码表 / `to_air` 的归一 / `validator` 的旗 /
> 分单提示词），**并且能指出规则号或版本号**。只是"我认同你说的有道理"不算已收，算**先放一放**。

四档用法：`待看`（新提默认）→ `已收`（落成规则，`ref` 填 `polish.POSTAL` 这类规则号或 `v1.33.0` 这类版本号）
/ `不采纳`（`note` 写清为什么）/ `先放一放`（认同但这轮不动）。只有管理员能改，改必填 `note`。

**双向可查**：落成规则那笔 commit 的 message 带 `board#<id>`，留档 §12 那一行也带上——从规则能倒查回
是谁哪条留言促成的，反过来也行。

采集在公司那台、落规则在我这边（那台不开任何长期入口，是业主定的），所以闭环需要一个"把内容带回来"的
动作：每条一颗**「复制这条」**，生成一段可粘贴文本（`board#7 · 郭健康 · 10-21 09:12 · 正文 · 国家 BR ·
收货人邮编 · 挂 NGB2609026G · 待看`；判过的再把每条判定连着那句话一起带上，如
`判定：已收 → polish.POSTAL（admin 10-22 10:04「已进表」）`），业主贴给我即可。这比导出 Excel 轻，
也不会出现"导出了一份 = 我处理过了"。

**不采纳的留言不删**：明年同一个人再提同一件事，指着那条说"去年说过为什么不做"，比重新讨论一遍便宜。

## 7. 测试策略（先红后绿，关键闸门做变异）

HTTP 行为（三角色 + 匿名各一档，学 `test_stats` 里 `_world()` 那套夹具）：

- 匿名 401；三角色都能发、都能读全表；本人改自己 200；**改别人的 403**；**非管理员改判定 403**；
  制单员硬删 403、管理员 200；`status` 不在四档 400；**追加判定而 `note` 空或超 200 字 → 400**；
  正文空/纯空白/超长 400；`tags.column` 不在列面 400；`BOARD` 没开时五条路由一律 404。
- **谎报署名两个方向都不许骗过**：请求里带 `by`/`role` 改不动留痕（同 `/stage` 那条"不信前端"的契约）。
- 撤回不销毁原文、重复撤回幂等；**撤回之后再 PATCH → 400**；改文本后旧文本仍在 `revised`。
- **改判不覆盖**：先标"已收"再标"先放一放"，`decisions` 两条都在、话都留着，`status` 等于最后一条；
  派生状态与文件里不重复存（写第二条 status 进文件的实现要被判红）。
- 两线程并发 PATCH 不丢行；`board.json` 写成半截时读回空表、服务不炸。
- **跑一轮自动清理后 `board.json` 原样还在**。

纯函数（node 驱动 `logic.js`）：状态中文映射、`counts`、筛选互斥且穷尽。
静态守卫：入口那颗存在**且不被 `applyRole()` 藏**、`.gate` 骨架 id 在 `index.html`、Esc 名单含 `boardWin`、
渲染函数里不许出现自己数 `counts` 的写法（禁 `reduce(`、`.filter(` 汇总）。

**变异清单（每条都要红）**：摘掉 403 判据 / 摘掉 note 必填 / 署名改成信请求 / 去掉列面白名单 /
撤回改成删行 / 撤回后仍允许改 / `decisions` 改成覆盖写 / 开关判据短路 / `counts` 改回前端算 /
入口塞进 `applyRole()` 的隐藏名单。

## 9. 明确不做

运行时生效（未审的自由文本绝不能决定发给公司的值）· 回复/讨论/@/已读回执 · 邮件或 IM 通知（要新增凭据
与失败重试，收益只是早半天看到，顶栏计数就是通知）· Excel 导出 · 图片附件 · 分页与归档 · 编辑别人的留言 ·
按机器名/端口自动判这台是谁（判据长在没人管的东西上，改端口就当场"消失"）。

## 10. 这一版要守的既有教训

- 界面状态必须等于留痕：一律按服务端响应画，不做乐观更新；计数由服务端给。
- 判据只写一处：列名取 fieldspec，状态四档取 config，中文映射取 logic.js，第二份副本迟早走偏。
- 共用集合的闸门（purge）新增数据文件必须显式钉一次。
- 静态守卫要钉"挂在哪个函数/哪条整行语义"，不钉元素名（同 `#thinkSelM` 与 `polishScan` 那两次教训）。
