# HAWB 主分单审核台 · 技术留档

> 定位：接手这套系统时需要一次读完的**总览 + 事实清单**。
> 深水区的设计理由在三份专项文档里（见 §13 索引），本文只写"现在是什么样、为什么这样、改的时候碰哪几处"。
> 版本：v1.0.5（2026-10-02）。所有数字（字段数、用例数、端口、阈值）都是当场从代码里核出来的，不是回忆。

---

## 1. 它在解决什么业务

空运货代的**分单（HAWB）录入核对**。原始票面是扫描件 / 照片 / PDF / Excel 电子单，制单员要照着它把 40 个字段敲进公司系统 j9 AMS。这套系统做三件事：

1. **读票**：把任意形态的票面变成结构化字段（大模型读图，不是模板匹配）。
2. **兜住错**：用确定性的手段判断"模型有没有抄错/漏抄"，把可疑项标成红旗摆到人面前。
3. **可逆地写回去**：人核对完，由人点提交，走公司接口回传；系统绝不自动提交。

一句话口径（用户定案，贯穿全库）：**漏抄比多红旗严重**。宁可多报几条红旗让人确认，也不能让一个错值静默进公司库。

## 2. 数据流：四层 + 一条并行链

```
上传文件
  └─ L0 归档      store.archive_original()      output/archive/<stem>/          原件 + manifest.json
  └─ L1 逐字转录  transcribe.py                 output/transcript/<stem>.json   每行 text + bbox（归一化 0-1000）
  └─ L2 结构化    vlm_extract.py                output/raw/<stem>.json          模型直出的全字段原文口径
  └─ L3 归一化    to_air.py + codes.py          output/air/<stem>.json          航空口径（码表/清洗/拆分）
  └─ 校验         fidelity.py + validator.py    output/qc/<stem>.json           保真回查 + 红旗
                ↓
      Excel（export_excel.py）/ 数据库（db_writer.py，可选）/ 审核台（server.py + web/）
```

- **L3 是 L2 的纯函数**：改归一化规则不重跑模型，`run_batch.py --recheck` 离线重算并补红旗。
- **L1 有两条来源**：扫描件走 VLM 转录；PDF/Excel 有文字层时 `transcribe_pdf_text_layer()` 直读（pymupdf），零模型调用且 bbox 精确。
- **主单（MAWB）是并行的一条链**，不是分单链的分支：`master_pipeline.py` 吃公司检索回来的 `AMS_RECORD` 文本 → L1 拼装 → L2 提取 → 清洗/红旗 → 缓存 → `mawb2` 回传。**引擎共用，契约各管各**（分单 40 列 ≠ 主单 36 列，见 §4）。
- **一张票走到哪一步，只有服务器知道**（2026-10-09 v1.2.0）。四个档从盘上现算，不看任何前端状态：
  有 `qc`=**parsed** → 另有 `staged/`=**staged**（人工核对结果已存服务器、**没发公司**）→ 在提交台账=**submitted**；`qc` 带 `error`=**failed**。
  读侧：`GET /tickets?date=&state=&mawb=`（`store.ticket_rows`，`/day` 就是它按天的视图）、`GET /staged/{stem}`、
  检索口 `/company/mawb` 多带一组 `pending`（本机已解析/已暂存而公司还不认识的票）。
  从前"解析了但没提交"只活在某个人的浏览器里（`S.tickets` + localStorage），换个人查同一张主单就是"没有分单"。
- **人工改的值与模型改的值分开存**：`air/`、`raw/` 仍是模型原样（重解析会覆盖，所以第一次暂存时快照进暂存档），
  人工终值在 `output/staged/<stem>.json`；主单同理（`ams_model`/`ams_final`）。

## 4. 字段契约：改一处，别改四处

- **分单 40 列**的家是 `fieldspec.py`：`DESK_FIELDS`（key/中文名/分组）+ `GROUP_LABELS`（单号 / 航路 / 货物与日期 / 发货人 SHIPPER / 收货人 CONSIGNEE）+ 类型表 `NUM` + 长文本表 `LONG`。
- 审核台表头那一块由 `deploy/gen_fields.py` 生成进 `desk.js` 的 `/* ==FIELDS== */ … /* ==/FIELDS== */` 区间；`--check` 用于查漂移（回归里有断言）。
- **主单 36 列**在 `master_fields.py`，列名必须跟公司 `AMS_RECORD` 逐字一致（IT 改过一次：`NOTIFYE_INFO_COUNTRY` → `NOTIFY_INFO_COUNTRY`，跟着改过一次）。
- 加/删一列要同时动：字段表 → prompt → L3 摘取 → 形态校验 → 保真正反查 → 审核台 → `schema.sql`。**回归里有 AST 扫描盯着硬编码列数**，散落的 `39`/`40` 会被抓。
- 老库要手工 `ALTER`：`schema.sql` 只做 CREATE，历史表补列在它注释掉的「老库升级」段里。

## 5. 模型渠道（L2 用什么读票）

预设表在 `config.MODEL_PRESETS`，**两家**，顺序即下拉顺序（2026-10-08 定案）：

| 预设键 | 渠道 | 实测结论（二十票横评，2026-09-24） |
|---|---|---|
| `intern-s2-official` | 官方书生 API（`chat.intern-ai.org.cn/api/v1`） | **兜底**（2026-10-08 起）。约 7-10 秒/张，免费无配额墙 |
| `qwen38-flash-bailian` | 公司百炼专属实例 MaaS（2026-10-04 从个人公共百炼 key 换来；`QWEN_API_KEY`，`sk-ws-` 开头，地址与 key 互不通用） | **默认**（2026-10-08 定案：优先公司 qwen，S2 降兜底）。保真 409/410、红旗 9 条，优于 S2 的 409/412、12 条，还解掉 S2 两处静默缺陷；比 S2 慢约 3 秒/票；预设里已关思考 |

**删过的渠道与原因**（别再当"漏接的选项"重新加回来）：

| 渠道 | 何时删 | 原因 |
|---|---|---|
| 魔搭三个（`intern-s2`/`qwen-flash`/`deepseek`）+ 北龙 `blsc-s2` | 2026-09-21 | 纯文本模型收图不报错直接照编；北龙配额未开通（400）；GLM-4V-Flash `max_tokens` 上限 1024 且难票上对调 MAWB/HAWB + 凭空编签发日期 |
| 小米 `mimo-v2.6-flash` | 2026-10-08 | 与 S2 平级（中位 7.2 vs 8.1s、保真同为 99.3%、红旗同为 12 条）却 p90 45-70s 长尾，且出现过一次 HAWB_NO **静默**错填（红旗没抓）——没换来收益 |
| 火山方舟 `doubao-seed-2-1-lite` | 2026-10-08 | 开思考 97-124 秒/票，只适合当"第二只眼睛"，而那条复核流程用户当时就没接 |

两家的 id 大小写、关思考写法各家互不通用等实测细节留在 git 历史（`config.py` 注释被删的那几段）。要临时试清单里的别的模型：`VLM_MODEL` 直接写模型 id，`resolve_model` 对未知键原样透传（走默认端点与 `MODELSCOPE_API_KEY`，拿不到预设的 base_url/密钥/extra_body，正式接仍需回到这张表）。

- **主单链单独一个开关** `MASTER_VLM_MODEL`，默认 `qwen38-flash-bailian`。理由：主单输入是几百字符纯文本、没有票面图，同一条主单 S2 花 97.8 秒只取到 2/36 列，qwen 7 秒取到 17/36。**别拿分单横评去推主单**。
- 换渠道的两种方式：审核台顶栏下拉热切（管理员）/ 改 `.env` 重启。缺密钥会在解析时直接报"渠道缺密钥"，**不静默回退**。
- 纯文本模型（`VLM_VISION=0`）机制保留但不推荐：它收到图片会把票面**编**成别的内容。扫描件会明确报错，电子单/文字层 PDF 可直读。
- 超时策略：`VLM_TIMEOUT=300`，超时只重试 `VLM_TIMEOUT_TRIES=2` 次（慢模型重跑还是五分钟，连撞三次只是把人钉在等待上），其他错误按 `VLM_RETRIES=3` 退避。
- 每个预设必须带 `max_tokens` 下限：实测有单次推理烧掉 19309 输出 token 的票，8192 被掐死 → content 空 → 连败三次。

## 6. 公司系统 j9 AMS 对接（唯一会写外部数据的地方）

六个路径，主单/分单各三：一读两写（**2026-10-09 文档改版**，末尾斜杠是契约的一部分）：
`/api/v1/j9/hawb`（读分单行）、`/hawb2`（**暂存**，恒落 `SEND_STATUS=0`）、`/hawb3`（**提交发送**，落 1）；
`/api/v1/j9/mawb/`（读主单）、`/mawb2/`（暂存）、`/mawb3/`（提交发送）。
两把 key 互不通用：`COMPANY_MAWB_KEY` 只能调 mawb 组、`COMPANY_HAWB_KEY` 只能调 hawb 组，串了 403。

> ⚠️ 改版前 `2` 就是"提交"。**我们 1.7.0 及之前所有标着"已提交"的票，其实都落在公司状态 0（暂存），
> 外围程序一条都不会取走**——1.8.0 把提交口挪到 `3`。历史那批需要人工到公司页面补点「提交发送」，
> 或改完再提交一次（状态 0 允许覆盖，所以能重发）。

五条硬规矩（都在 `company_api.py`，都有用例）：

1. **先读后写**：写之前先读回那一行，读不到就拒（不能凭本地数据猜公司侧状态）。
2. **SEND_STATUS 闸门只认 0**：`1 已提交发送（还没发出去）`、`2 外围已发送成功` 两档公司都回 400「已提交，不能更新」，本地先拦下、一个写请求都不发。从前放行 2 是拿旧文档读的，等于允许去覆盖一条已发成功的记录。界面措辞跟着字典改（`0 公司暂存（未发送）/ 1 已提交发送·等外围 / 2 公司已发送成功（锁定）`）——从前把 1 写成"已发送"会让人以为发出去了，把 2 写成"已改·待重发"会诱导人去改锁死的行。
3. **整表写回 + 全字段都要在**：没给的列会被写成 NULL，所以读回来的原值要一起带上；IT 2026-10-09 又要求**列面一列不许缺**，没值的发 `null`（`HAWB_SUBMIT_COLS` 由 `fieldspec.DESK_FIELDS` 推出来，不抄第二份表）。空数字格必须发 `null` 而不是 `""`——空串会被公司判「PIECES 必须为整数」整条退回。
4. **税号统一进 EORI**：公司列面（主单 39 / 分单 38 列）**没有税号格**，IT 定案所有税号（USCI/CNPJ/RFC/GST/VAT）填进同主体的 `*_INFO_EORI`；同主体既有 EORI 又有 VAT 时**两个都留，用 `" / "` 拼在一格**。`merge_ids()` 先拆再拼（暂存能反复写，不拆每写一次就多挂一段）。分隔符**必须带空格**：CNPJ 自己印成 `07.454.234/0001-10`，裸斜杠会把一个号码拆成两段（有用例钉住）。EORI 形态粗检因此退一步只守"像不像号码"（按空格拆段、去标点、比形状），不再按位数认 USCI。
5. **幂等锁** `GUARD_TTL = 90`：同键同内容 90 秒内不重复写（`output/submit_guard/`，一锁一文件）。**接公司暂存时这条要分开**：暂存与提交内容相同是常态，共用一把锁会让"暂存完紧接着提交"的第二次被当连点吞掉。

限流与重试：IT 文档写每把 key 10 次/秒、200 次/分钟、3600 次/小时，本地默认 `J9_RATE_PER_SEC=8` 留两成余量；读 10s / 写 20s 超时；429/5xx/连不上退避重试 `J9_RETRIES=3`，**400 业务错不重试**。`COMPANY_API_MODE=mock` 时只回本机回执不外发（默认，回归与端到端验证都靠它）。地址必须带端口：`http://j9aiaeapi.justrightlog.com:18080`（80 端口是这台服务器上的别的服务）。

公网是 http 明文，所以两把 key 按"可轮换"对待。

## 7. 审核台前端（形态③，日常主入口）

- **零构建**：`logic.js` 装纯逻辑（全局 `L`，尾部一行 `module.exports` 只为让 node 能读），`desk.js` 只碰 DOM。`index.html` 里 logic.js 必须排在 desk.js 前面（有断言）。
- **子路径自适应**：`BASE = location.pathname.replace(/\/(index\.html)?$/, "")`，所以挂在 `/hawb/` 下和根路径下都能用；静态资源走 `/web/{asset}`，`no-store`。
- **两个视图 + 一张统计窗口**：核对工作台 / 今日台账（`/day`，按日期聚合当班录入与红旗）；**统计**（`/stats`，见 §9 的口径）不占页面，是顶栏那颗按钮开出来的一张浮层窗口（`#statsWin`，与「账号管理」同一套 `.gate` 形状）——从前它是压在页面最下面的一节，永远比核对区矮半截，要滚到底才看得见，也没法一边开着票一边看数。**入口与接口都只对管理员**（2026-10-09 业主定案）。左侧 48px 状态窄轨 + 置顶待办条 + 底部常驻操作条。
- **票面浏览演进（重要）**：早期把 PDF 交给浏览器内嵌阅读器，结果 ① Chrome 的缩略图侧栏吃掉近一半宽度；② 窄高栏里 `view=Fit` 与 `view=FitH` 算出**同一个缩放**，按钮点了没反应；③ Edge 完全不理 `navpanes=0`，侧栏关不掉。v1.0.3 起**票面一律走我们自己的 `/render` 页图**（服务端 pymupdf 按页转 PNG，页数从响应头 `X-Ticket-Pages` 拿），v1.0.4 加"按住拖动"，v1.0.5 加"滚轮缩放"。
  - 缩放算式全在 `logic.js`：`wholePagePct`（整页所需图宽，占栏宽百分数）、`maxZoomPct`（不许超过渲染像素，A4@scale2 在 675px 栏位 = 176% 见底）、`zoomStep`（滚轮乘法步进 ±15%，25–400%）、`zoomAnchor`（钉住光标下那一处）、`canPan`（内容真超出才给抓手）。
  - 两条反复强调的判据：**不给"看着能拖其实拖不动"的假抓手**；只剩一档的按钮就藏掉。
  - 监听滚轮必须 `{passive: false}`，否则 `preventDefault` 被忽略、滚轮还是去滚整页。
  - 只有拿不到归档（那张票早于「上传一律落盘」上线，或归档被清理过）才退回浏览器阅读器，那条路径保留三档循环（`pdfBox`/`viewCycle`/`firstView`）。
- **点字段定位票面**：点右侧字段名 → `/layout/{stem}` 取 L1 行 bbox → `/render` 页图打底 → 高亮 + 滚到那一行。**放不放大、放多大是各人的手感**（v1.4.0，用户要的开关）：定位那条工具条里有「定位时：自动放大 / 固定倍数 / 不放大」+ 一个百分比框，偏好存本机 localStorage（`hawb.review.locate.zoom`，默认 `auto`）——**只存内存不算开关**（刷新就回默认），**只藏按钮也不算**（"不放大"要把上一次的倍数收回到 100%，否则只挡得住第一次）。倍数与上限的算式在 `logic.js`：`autoZoomPct`（命中行约占窗格 1/3，100–500%）、`locateZoom`（三档合成一个倍数，`null`=不放大；`fixed` 与 `auto` 都不许超过 `maxZoomPct`，填超了落到上限并 toast 说清实际用了多少，同时把上限写进输入框的 `max`）。
- **两档"存"分开**（v1.2.0）：**暂存** = 存到服务器（`/stage`、主单 `/master/stage`），同事检索得到、**结构上发不出公司**；**提交** = 回传公司（`/submit`）。本机 localStorage 那块改口「本机未保存的编辑」——同名会让人以为点了就交上去了。打开别人暂存的票时服务器那份赢，本机未存的改动不删但点名（`L.stagedMerge`）。
- **草稿**：编辑存本机 localStorage（`L.draftMerge/draftPut`），提交成功后仍可回看；解析值与草稿原值不一致的列才算"打架"，不无脑覆盖。
- **宽窄与框高都交给人（v1.5.0，值框的宽 v1.6.0，一个斜角自由拖 v1.7.0）**：四样手感都能自定义，全部存本机 localStorage（各人屏幕不一样，不该互相将就）——
  ① 长文本格拖出来的高度：`L.fieldHeight(记录值, 内容高)`，**记过那一列就以拖的为准**，`autoGrow` 不再按内容重设它（从前它每下输入都重撑，拖完一打字就弹回去，"能拖"等于"不能自定义"）；原生 resize 不触发任何事件，只能 `pointerdown` 记高、`pointerup` 比对；恢复出口是待办条/主单工具条上的「框高恢复（N）」槽位（`.fhslot`，拖完当场刷出来，不重画整表以免弄丢正在编辑那格的光标）——**不用双击**，双击在文本框里是选词。
  ② 票面栏↔字段栏那道缝（`#gripView`，网格多出一条 10px 轨）：存 `--vw`（票面栏占整行的**百分数**），两侧各留 260px 底线。
  ③ 字段名列宽（表头右边界那道 `#gripCol`）：存 `--colK` 像素。
  ④ **值格右边界那道 `.edg`**（v1.6.0，`edgeGripHtml()` 画在每一格上，分单表与主单表两处模板都要接）：往右拉 = 值这一列更宽，宽度是从票面栏那头扣的，所以它写的就是 ② 那份偏好（`LS.split` / `--vw`，共用 `deskGeom()`+`saveDeskShare()`，两个入口一份数）。算式 `L.boxWidthPct(票面宽, 右拉像素, 整行宽, 底线)`——**方向最容易反**（反了就是"想拉宽结果更窄"），单独一个函数单独一条用例。堆叠态（≤1460px）没有另一侧可挤，`.edg` 与 `#gripView` 一起 `display:none`——留着就是按住不动的假抓手。三道把手都可键盘方向键调，都带 `role="separator"`。
  ⑤ **一个斜角同时管宽高（v1.7.0，用户："可以自由拖拽改变大小的"）**：短字段从前是 `<input>`，而**原生 resize 只长在 textarea 上**，所以值列一律换成 `rows="1"` 的 textarea（`.one` 标单行，`blockEnter` 挡住回车——这个值原样写进公司系统，换行进去就是脏数据；数字列留住 `inputmode="decimal"`）。斜角拖的看起来是"这一格"，但值是一整列：`pointerup` 时高按列记进 `LS.fieldH`，**宽那一下换算成整列份额**（走 ④ 同一份偏好）并**把 inline 宽擦掉**（不擦那一格从此钉在自己的宽度上，下次调列宽调不到它）。
  ⑥ **高度上限分两种人说（v1.7.0）**：CSS 的 `max-height` 会**连人拖的一起卡住**（原生 resize 尊重它），所以渲染层只留 900px 那道"别把页面撑爆"的硬边界，"没人拖过就按内容撑"的 320 上限挪进 `L.fieldHeight` 的自动那一支。
  ⑦ 两处只有浏览器能发现的（v1.7.0 实测）：状态列的宽从前只写 `td.s{width:120px}`，fixed 表格不认 ⇒ 它和值列**平分剩余空间**，值框白窄一半（316→529px，修在 `th.scol`）；`th.kcol` 为安置表头把手写过 `position:relative`，把全局 `th` 的 `sticky` 顶掉 ⇒ 表头第一格跟着内容滚走、右边两格还粘着（sticky 本身就是定位上下文，不用另写）。

- 主单视图借同一对面板，但那一栏是"资料文本"不是票面图，点字段不能定位——界面上写明了。

## 8. 登录、账号与安全边界

- 登录是**唯一**门禁（`auth.py`）：pbkdf2 口令哈希 + HMAC 签名会话 Cookie；`users.json` 存哈希与 secret。历史上的 `HTTP_API_KEY`/`X-API-Key` 已连根删除。
- 三角色：`admin`（可切模型、管账号、看统计）/ `reviewer` 制单员（上传、核对、暂存、提交）/ `inputter` 录入员（读别人的暂存、复核、提交）。`require_web` / `require_admin` 只认会话；业务口**只有统计这一处**按角色分档——`/stats` 与 `/stats/export` 都是 `require_admin`（2026-10-09 业主定案："统计只给管理员"）。藏按钮不算门：导出那条链接是同一份数的另一种拿法，两处都得挡（`test_stats_is_admin_only_for_page_and_export`）。其余口仍不分档——现有角色就这三个，收全部角色的门等于没有门（早年那道"只让录入员和管理员用检索"的守卫随 2026-09-26 的并入删掉了，别再按它理解权限）。
- 发送公司前**三道门**（`/submit`，主单 `/master/submit` 同构）：号要齐 → 红旗按当前值重算并逐条确认 → **没有"录入员复核过的暂存记录"就要多点一次确认**，并留痕 `no_inputter_review`。用户定案是"制单员仍可直发，但要额外确认并留痕"：留痕不是为了拦人，是为了以后能算出"跳过复核直接发的那批错得多不多"。
- 首启种下 `admin/admin123` + 8 位制单员（种子口令为空，登不进）+ 3 位录入员。**上线第一件事：改 admin 口令并给制单员下发口令**。
- 这件事不再只写在文档里：`auth.admin_still_uses_seed_password()` + `/api/me` 的 `admin_pw_default` 会让顶栏给管理员亮一颗「口令未改」（点了直接进账号管理，改完当场灭）。**故意不放 `/health`**——那个端点免登录，等于站在门外告诉对方管理员还是默认口令；也不发给制单员（改不了的人不必被推，少一处出现少一处泄露面）。
- 密钥与本机文件：`.env`、`users.json`、`output/`、`input/`、`_quarantine_20260920/`、IT 那份带真 key 的《AMS录入接口调用说明》全在 `.gitignore` 里，并有 `tests/test_gitignore.py` 拿 `git check-ignore` 逐个问一遍（源码文件被误挡也会红——部署清单取自 `git ls-files`）。
- 提交动作只由人点。回传失败的原因会带票号落到服务日志（`journalctl -u hawb-desk` 可查），不只在响应里一闪而过。

## 10. 测试体系（392 项，零 pytest）

- 入口 `python -X utf8 tests/run_tests.py [过滤词]`，自定义 runner，35 个 `tests/test_*.py` 自动发现。
- **离线**：不打真实模型、不连公司系统（`mock` 模式 + 桩）。真调用类的验证另放 `poc/`（目前只剩主单模型横评 `poc/master_model_compare.py`，跑一次花额度）。
- 前端纯逻辑用 **node 驱动**（`tests/web_src.py` 的 `logic()`），不引 jsdom；机器上没 node 算**失败**，不算跳过。
- 静态契约扫描是一类重要用例：`test_imports.py`（跨模块私有调用、退役层复活）、`test_fieldspec.py`（字段块漂移、硬编码列数）、`test_server_http.py`（页面里所有 fetch 必须带 `BASE` 前缀、`[hidden]` 必须有 CSS 兜底、`/health` 字段）、`test_env_doc.py`（`.env.example` 覆盖所有真实配置键）、`test_console.py`（GBK 控制台可读性）。
- 前端样式四条守卫（2026-10-03 v2 改版立的，先写红再做绿）：**色值只准出现在 `tokens.css` 的变量定义上**（`desk.css`/`index.html`/`desk.js` 里一个 hex 或 rgba 都不许）、**内联 `style=` 只准留当场算出来的那几个**（票面 bbox 百分比、台账列宽）、**`--hdh`/`--todoH` 必须由 JS 实测写入**（样式里不许留 `top:64px` 这类抄来的魔法数）、**状态填充色不得当文字色用**（`color:var(--c-ok|warn|bad)` 直接判违规）。对比度那条按"这个字实际压在什么底上"配对来算，不是所有文字乘所有底色。
- 惯例：**先写红用例再动手**；改完跑全量；关键闸门要做**变异验证**（把规则删掉看测试是否真的红——"闸门自己也要被验证"）。
- 暂存这一档的三条保证各有用例（`tests/test_staging.py`）：**暂存 Structural 不发公司**（把 `_company_submit`/`submit_order`/`submit_master` 打成 `raise AssertionError`，点暂存仍要 200）、**逐字段差异由服务器算**（前端谎报 `edited_fields` 两种方向都不许骗过统计）、**基线只在第一次暂存快照**（重解析覆盖 `air/` 后仍查得回模型原样）。主单侧同三条在 `test_master_http.py`。
- 统计的口径写在 `tests/test_stats.py` 里当契约：分母只算"可比列"（两边都空不算、`SEND_STATUS` 恒为模型硬写要排除）、没留痕的历史台账进 `legacy` 不进分母（否则 17 条老记录会把修改率算成 0%）、导出 Excel 的数必须与 `/stats` 一字不差；逐张那一行的号（台账优先于暂存、缺号留空）也有用例。
- 回归入口会比对**这台机器的真东西**（`.env`/`users.json` 的字节+mtime、`output/` 的文件清单），跑完不一致就整场判失败。两次真实事故：一次 `/model` 写回真 `.env`（等于每次部署都把线上模型选择改回去），一次某条用例漏指 `OUTPUT_RAW_DIR`、往真 `output/raw` 落了一份假 L2——本机因为残留同名文件查不出来，是这份清单在干净的 VM 上抓到的。
- L3 基线：`fixtures/l3/{input,expected}`，有意改归一化后 `--update-baseline` 复核差异再更新。

## 15. 踩过的坑（这一节最值钱，改代码前扫一眼）

1. **闸门自己也要被验证**。`sync.sh` 的回归闸门曾是空的（`| tail -3` 让退出码变成 `tail` 的 0），"部署成功"却没人跑过测试。同类：`tar` 不删远端已删文件 → 线上留孤儿模块。
2. **Windows 控制台是 cp936**。把 stdout 强改 UTF-8 不崩，但用户看到的是一整屏乱码；只设 `errors="replace"`。`.bat` 是 GBK+CRLF，**绝不能用按 UTF-8 读写的编辑器改**（有断言要求"仍能按 GBK 解码"）。
3. **别用 heredoc 写含中文/反斜杠的源码**：`\b` 会落成退格符，正则照旧编译通过却谁也匹配不上。
4. **`git commit -m "..."` 里别放反引号**：双引号内的 `` ` ` `` 会被 bash 当命令替换执行，提交照样成功但那半句没了。
5. **ssh 远端命令的退出码会被管道最后一条吞掉**，本地 `pipefail` 管不到远端 shell；要判成败就 `; echo \$?` 带回来。
6. **真实票名带 U+00A0 不间断空格**（`016-82445790\xa0分单`），手敲普通空格去调 `/render` 会 404；票面里的连字符常是 U+2010，重音字母会拆码位。
7. **改 `.py` 必须重启服务**，而重启会踢掉在线会话；css/js/文档用 `--no-restart`。出现过"服务端跑的是旧进程、新功能像坏了"的静默失效，`/health` 的 `stale_files` 就是为此存在。
8. **阅读器的地址参数两家不通用**：Chrome 认 `navpanes=0`，Edge 完全不认（只认 `toolbar=0`）。凡是把表现交给第三方内嵌组件，就要按"最保守那家"设计，或干脆自己渲染。
9. **界面控件点了必须有反馈**。"两个选项在某种版式下算出同一个结果"就是死按钮（`Fit`/`FitH` 撞车、抓手残留），判据要写进测试。
10. **口径别替用户放大**：USCI 可以填 EORI，不等于"什么号都能塞 EORI"；主单税号非 USCI 的那类要问 IT，不猜。
11. **内联样式的最大源头不在 HTML，在 JS 的模板字符串里**。盘点时只数 `index.html` 会数出 8 处，实际 `desk.js` 里还有 32 处——它们不吃令牌、在样式表里搜不到，去卡片化/换色板那天必然漏。守卫要扫 `desk.js`，并允许"当场算出来的值"留在行内（票面 bbox 的百分比、台账的列宽比例）。
12. **给 sticky 容器做浮层，要连层叠上下文一起想**。`position:sticky` 自成层叠上下文：窄轨展开列表写 `z-index:70` 也只在这个上下文里比，压不过 DOM 更后的 `#view`/`#main`。当时没撞上是靠"列表 286px 宽 < 栏位起点 340px"侥幸，窗口一窄就露馅。层级要给在容器自己身上（`.rail{z-index:var(--z-rail)}`）。同理 `--z-toast` 必须高于 `--z-gate`：那条"登录已过期"正是和遮罩同时弹的。
13. **对比度按角色算，不按颜色算**。同一种绿，当状态点 ≥3.0 就够，当 11px 小字要 ≥4.5——所以 `--c-ok`（填充）和 `--c-ok-text`（文字）是两个令牌，别为了少写一行而共用。算的时候还要按"这个字实际会压在什么底上"配对：去卡片化会把文字从白底搬到页面底，那一档差 0.5~0.7。
14. **会随宽度变高的高度不能写死**。顶栏在 1920/1500/1200 三档实测是 97/96/135px，而样式里三处 sticky top 抄的是 64px、令牌里写的是 54px——1200 那一档差 81px，票面栏会顶进顶栏底下。`--hdh`/`--todoH` 一律由 `measureChrome()` 写回，`ResizeObserver` 负责重测。
15. **改 JS 模板里的 HTML 属性时盯紧引号嵌套**。`"<b style='color:#8c4a17'>"` 换成 `class="svc-warn"` 会把双引号撞进双引号字符串里，整份 `desk.js` 语法报废——这条被"生成的 JS 要能被 node 解析"那类用例当场抓住，不是靠肉眼。
16. **写盘的用例必须指开每一个目录**。一条提交用例漏指 `OUTPUT_RAW_DIR`，就往运维机的真 `output/raw` 落了一份假 L2，后面三条用例读到它、报出凭空的红旗。本机**查不出来**（上一次跑已经留了同名文件，前后一致），是部署时的回归闸门在干净的 VM 上抓到的——所以入口现在比 `output/` 的文件清单，不止比 `.env`。加新用例时先问一句：这条链路上有几个目录？
17. **删掉一个开关，要连"读它的那条分支"一起删**。去掉「落盘留档」复选框后，`desk.js` 里 `if (t.file && !t.save)` 会恒真（`t.save` 再没人赋值），图票于是永远拿浏览器里的 Blob 当底图、`LOC.remote` 判错——**功能表面正常，定位模式悄悄退化**。守卫断言的是 `t.save` 这个标识符不许再出现，而不是断言那个分支还在。
18. **输入校验别挂在可替换的单例上**。把 `server._safe_stem` 改成转调 `store.safe_stem` 逻辑上更对（写文件与读文件同一条规则），但测试会把 `server.store` 整个换成桩，于是 10 条读票面的用例一起报错"桩上没有这个方法"。改成模块级绑定 `_safe_stem = store.safe_stem`：判定只有一份，换桩也换不掉它。
19. **守卫要断言"带条件的写法"，不是断言字符串存在**。前端把"未经录入员复核"的确认写成无条件 `acked_no_review = true`，那条 `assert "acked_no_review" in js` 照样绿——是拿变异验证（把它真的改成无条件）才发现的。同类：注释里写出 `fetch(` 会被 BASE 前缀守卫当调用点抓下来，说明文字也得避开被扫的那个子串。
20. **两个百分比不是一回事**。`acc_field`（模型读得准不准）与 `acc_after_review`（复核之后人还剩多少活）共用分母、含义相反方向；拿去回答"能不能直接对接平台"的必须是后者。同理"没暂存记录"的票要把改动记到制单员档而不是记 0——记 0 会系统性抬高正确率，而**抬高方向的误判会答应下本来不该接的对接**。
21. **`release.sh` 要求版本号是"未提交"的状态**。它自己做 `sed 改号 → git add config.py → git commit`；如果发版前已经手工把版本号提交过（2026-10-09 就这么撞了一次），它那句 commit 变成"nothing to commit"，而脚本是 `set -e` —— **就地中断，后面的打 tag、推服务器、推 GitHub 一步都没做**，退出码却容易让人以为发完了。所以：要么把版本号留给脚本去改，要么中断后手工补齐这三步并自己核 `/health` 与远端 tag。
22. **前端用例比的是 JSON 的值，不是类型——值的类型要单独钉**。服务器暂存记录里 `WEIGHT` 存成了 `1234.5`（浮点）、`PIECES` 存成了 `77`（整数）：那是 `store.field_diff` 归一后的样子。`L.stagedMerge` 把这同一份值原样塞进 `airE`，核对页渲染到 `l3.trim()` 就抛 `l3.trim is not a function`，**整页字段一个都不出来，屏幕上是"上传分单后在这里逐字段核对"**——像没打开票，其实是被异常打断在半路。node 那条用例当时全绿：`assert r["airE"] == {"PIECES": 77}` 里的 77 与 "77" 它不分。现在合并函数出口一律 `String()`，并有一条用例专门断言"值必须全是字符串"。教训 generalize 一句：**跨语言边界（Py↔JS）传的数据，形状也是一种契约**。
23. **"哪几列算改动"只允许有一份算术**。`stagedMerge` 从前自己拿 `air_model` 与 `air_final` 比字符串：45.0 与 45 一比，一列谁都没动过的值挂上了改动标记（人随即开始怀疑所有标记）。服务端早就用 `store.field_diff`（数字按数值比）算好了 `edits`，前端改成直接认它。同一条规则下主单记录补了顶层 `edits`，与分单同形——**统一的是机制，不是字段面**。
24. **指标的名字必须圈住它数的那些行**。「未经录入员复核就发出」从前把所有 `no_inputter_review` 的行一起加，于是**只暂存、压根没发**的票也进去了：数会随谁把工作停在暂存那一档而涨，而它是拿去看要不要对接平台的数。行上的标记照旧留（那是这张票自己的复核状态），合计只数 `state == "submitted"`。
25. **CSS 变量不能拿去乘 `1fr`；fixed 表格只认表头给的列宽**。给分栏写 `minmax(420px, calc(var(--vr) * 1fr))`，Chrome 判整条 `grid-template-columns` 非法、掉回自动布局：把手那一轨变成 0px，两栏再也不跟着变量变——静态用例全绿，只有量 `getBoundingClientRect()` 才看得出来。改成 `minmax(420px, var(--vw))`（百分数）就好：`var()` 替进 `minmax` 是支持的，坏的是 `calc()` 里拿变量去乘 `fr`。同一轮另一处：`table-layout:fixed` 下列宽写在 `td.k` 上不生效（量出来一直是 276px，不是我设的 366px），要写在 `th` 上。**凡是"拖了有没有反应"这类事，断言只能钉形状，生效与否必须在浏览器里量。**
26. **用户点名要"改文本框的宽度"，就别回给他"其实是这一列的宽度"**（2026-10-09 连着被推回两次，第二次原话"我只想单纯的可以改变文本框的宽度"）。效果上两者是一回事——fixed 表格里一格宽了整列就宽了，而这一列的宽又是"整行减去票面栏"；但**入口必须画在他手指指着的那个东西上**，于是每格右边界一道 `.edg`，拖它 = 值列宽 = 从票面栏扣，写的是分栏那道把手同一份偏好。顺带一条否掉"用原生 `resize:both` 就好"的硬事实：**`resize` 对 `<input>` 不生效**，值列里一半是 input，只让长文本能拖宽比都不能拖更让人以为坏了。同一类坑还有"底线"：挤到 `minmax(420px, …)` 那一档时票面栏不再让路，把手就该停住（实测停在 420px、`#main` 不出横向滚动条），而堆叠态压根没有另一侧可挤，就把把手整条藏掉——按住不动的假抓手比没有把手更糟。
27. **同一件事第三次栽在"fixed 表格只认表头那一行"上**：状态列的宽从前只写 `td.s{width:120px}`，Chrome 直接不认 ⇒ 表头那格成了"没给宽度的自动列"，于是它和值列**平分剩余空间**，值框长期只有应有宽度的一半（实测 316px，修到 529px；拖 120px 只长 60px 就是它的影子症状）。同一轮另一处：`th.kcol` 为了让表头把手贴住右边界写了 `position:relative`，把全局 `th{position:sticky}` 顶掉 ⇒ 字段表滚起来"字段"那一格跟着走、右边两格还粘着。**sticky 本身就是定位上下文，absolute 的子元素照样贴得住**，别另写 relative。⇒ 布局上的每一条声明都要问一句"生效的那一层是哪一层"，而答案只有浏览器量得出来。
28. **CSS 上限会连原生拖拽一起卡住**：`td.v textarea{max-height:320px}` 本意是"自动撑别撑爆卡片"，但原生 `resize` 尊重 `max-height` ⇒ 人只能拖到 320px，"自由拖拽"就半废。改法是把两种人说清：渲染层留 900px 那道硬边界，"没人拖过就按内容撑"的上限进 `L.fieldHeight` 的自动那一支（320）。同类判断：**一条约束如果同时管着"系统自己做的"和"人主动做的"两件事，就得拆开写。**
29. **外部契约最阴的一种改动：端点没变、含义翻了面**。IT 2026-10-09 的改版把 `2` 从"提交"改成"暂存"、新加的 `3` 才是提交发送——我们代码一行不报错、回归全绿，而**所有标着"提交成功"的票在公司侧都是状态 0，外围程序一条都不会取走**。⇒ 拿到新版接口文档，要问的不是"路径还在不在"，而是"每个写口落什么状态、谁能覆盖谁、锁在哪一档"。这类语义只能有用例钉住：现在 `test_*_goes_to_the_send_endpoint` 钉住走 `3`，闸门"只认 0"也各有用例（放行 2 的那条是拿旧文档写的，等于允许去覆盖一条已发成功的记录）。附带一条：j9 假桩被四个测试文件各抄一份，端点一改同时炸八条 —— **判据（哪条路径算写口、回执长什么样）收敛进 `tests/j9_fake.py` 一处**。
30. **拼串的分隔符要挑"数据里不会出现的那个"**：税号统一进 EORI 后，同主体两个号要拼在一格，最先想到的 `" / "` 正好撞上巴西 CNPJ 自己的斜杠（`07.454.234/0001-10`）——裸斜杠一切，一个号码变两段，再拼回去就永久坏了。定成**两侧必须带空格的 `" / "`**，并留一条用例拿 CNPJ 专门试（把正则改成允许裸斜杠，那条就红）。同理，凡是"能反复执行"的合并（暂存会反复写同一格）必须**先拆再拼**，否则每写一次多挂一段。
