# HAWB 主分单审核台 · 技术留档

> 定位：接手这套系统时需要一次读完的**总览 + 事实清单**。
> 深水区的设计理由在三份专项文档里（见 §13 索引），本文只写"现在是什么样、为什么这样、改的时候碰哪几处"。
> 版本：v1.0.5（2026-10-02）。所有数字（字段数、用例数、端口、阈值）都是当场从代码里核出来的，不是回忆。

---

## 1. 它在解决什么业务

空运货代的**分单（HAWB）录入核对**。原始票面是扫描件 / 照片 / PDF / Excel 电子单，制单员要照着它把 40 个字段敲进公司系统 j9 AMS。这套系统做三件事：

1. **读票**：把任意形态的票面变成结构化字段（大模型读图，不是模板匹配）。
2. **兜住错**：用确定性的手段判断"模型有没有抄错/漏抄"，把可疑项标成红旗摆到人面前。
3. **可逆地写回去**：人核对完，由人点提交，走公司接口回传；系统绝不自动提交。

一句话口径（用户定案，贯穿全库）：**漏抄比多红旗严重**。宁可多报几条红旗让人确认，也不能让一个错值静默进公司库。

## 2. 数据流：四层 + 一条并行链

```
上传文件
  └─ L0 归档      store.archive_original()      output/archive/<stem>/          原件 + manifest.json
  └─ L1 逐字转录  transcribe.py                 output/transcript/<stem>.json   每行 text + bbox（归一化 0-1000）
  └─ L2 结构化    vlm_extract.py                output/raw/<stem>.json          模型直出的全字段原文口径
  └─ L3 归一化    to_air.py + codes.py          output/air/<stem>.json          航空口径（码表/清洗/拆分）
  └─ 校验         fidelity.py + validator.py    output/qc/<stem>.json           保真回查 + 红旗
                ↓
      Excel（export_excel.py）/ 数据库（db_writer.py，可选）/ 审核台（server.py + web/）
```

- **L3 是 L2 的纯函数**：改归一化规则不重跑模型，`run_batch.py --recheck` 离线重算并补红旗。
  唯一不参与归一的是**发货人/收货人整串**（`SHIPPER_INFO`/`CONSIGNEE_INFO`）：那一列只许是票面那一格的照抄串，
  代码一个字符都不动（v1.24.0，见 §15 第 67 条）。同主体的子列照常归一（国家落两字母码、电话清成号码本体、税号并进 EORI）。
- **L1 有两条来源**：扫描件走 VLM 转录；PDF/Excel 有文字层时 `transcribe_pdf_text_layer()` 直读（pymupdf），零模型调用且 bbox 精确。
- **主单（MAWB）是并行的一条链**，不是分单链的分支：`master_pipeline.py` 吃公司检索回来的 `AMS_RECORD` 文本 → L1 拼装 → L2 提取 → 清洗/红旗 → 缓存 → `mawb2` 回传。**引擎共用，契约各管各**（分单 38 列 ≠ 主单 36 列，见 §4）。
- **一张票走到哪一步，只有服务器知道**（2026-10-09 v1.2.0）。四个档从盘上现算，不看任何前端状态：
  有 `qc`=**parsed** → 另有 `staged/`=**staged**（人工核对结果已存服务器、**没发公司**）→ 在提交台账=**submitted**；`qc` 带 `error`=**failed**。
  读侧：`GET /tickets?date=&state=&mawb=`（`store.ticket_rows`，`/day` 就是它按天的视图）、`GET /staged/{stem}`、
  检索口 `/company/mawb` 多带一组 `pending`（本机已解析/已暂存而公司还不认识的票）。
  从前"解析了但没提交"只活在某个人的浏览器里（`S.tickets` + localStorage），换个人查同一张主单就是"没有分单"。
- **人工改的值与模型改的值分开存**：`air/`、`raw/` 仍是模型原样（重解析会覆盖，所以第一次暂存时快照进暂存档），
  人工终值在 `output/staged/<stem>.json`；主单同理（`ams_model`/`ams_final`）。

## 4. 字段契约：改一处，别改四处

- **分单 38 列**的家是 `fieldspec.py`：`DESK_FIELDS`（key/中文名/分组）+ `GROUP_LABELS`（单号 / 航路 / 货物与日期 / 发货人 SHIPPER / 收货人 CONSIGNEE）+ 类型表 `NUM` + 长文本表 `LONG`。2026-10-10 删掉 `*_INFO_TAX_ID` 两列（40 → 38），识别号只剩 `*_INFO_EORI` 一个格子。
- 审核台表头那一块由 `deploy/gen_fields.py` 生成进 `desk.js` 的 `/* ==FIELDS== */ … /* ==/FIELDS== */` 区间；`--check` 用于查漂移（回归里有断言）。
- **主单 36 列**在 `master_fields.py`，列名必须跟公司 `AMS_RECORD` 逐字一致（IT 改过一次：`NOTIFYE_INFO_COUNTRY` → `NOTIFY_INFO_COUNTRY`，跟着改过一次）。
- 加/删一列要同时动：字段表 → prompt → L3 摘取 → 形态校验 → 保真正反查 → 审核台 → `schema.sql`。**回归里有 AST 扫描盯着硬编码列数**，散落的 `39`/`40` 会被抓。
- 老库要手工 `ALTER`：`schema.sql` 只做 CREATE，历史表补列在它注释掉的「老库升级」段里。

## 5. 模型渠道（L2 用什么读票）

预设表在 `config.MODEL_PRESETS`，**两家**，顺序即下拉顺序（2026-10-08 定案）：

| 预设键 | 渠道 | 实测结论（二十票横评，2026-09-24） |
|---|---|---|
| `intern-s2-official` | 官方书生 API（`chat.intern-ai.org.cn/api/v1`） | **兜底**（2026-10-08 起）。约 7-10 秒/张，免费无配额墙 |
| `qwen38-flash-bailian` | 公司百炼专属实例 MaaS（2026-10-04 从个人公共百炼 key 换来；`QWEN_API_KEY`，`sk-ws-` 开头，地址与 key 互不通用） | **默认**（2026-10-08 定案：优先公司 qwen，S2 降兜底）。保真 409/410、红旗 9 条，优于 S2 的 409/412、12 条，还解掉 S2 两处静默缺陷；比 S2 慢约 3 秒/票；预设声明了思考参数、默认档关着 |

**思考模式是一个全局三档开关**（`MODEL_THINKING`，2026-10-10 用户要）：`""` 跟随预设 / `"0"` 关 / `"1"` 开。生效面由**预设自己声明**（`"thinking": {"param": "enable_thinking", "default": False}`），只有 qwen 这一家：官方书生压根不接受 `extra_body`，硬塞一个参数就回 400，所以在它上面拨到哪一档都不发任何东西。三处都跟着这个真值走，免得界面说谎：`model_extra_body()` 决定发什么、`resolve_model()` 的标签带「· 思考开/关」（切换提示与主单下拉用它）、审核台顶栏那个「思考」下拉（仅管理员，`POST /model/thinking`，写回 .env 与模型选择同一条路）。代价说在界面上：开思考多烧几千 reasoning token、单票更慢；`VLM_TIMEOUT` 300 秒不用动。

**删过的渠道与原因**（别再当"漏接的选项"重新加回来）：

| 渠道 | 何时删 | 原因 |
|---|---|---|
| 魔搭三个（`intern-s2`/`qwen-flash`/`deepseek`）+ 北龙 `blsc-s2` | 2026-09-21 | 纯文本模型收图不报错直接照编；北龙配额未开通（400）；GLM-4V-Flash `max_tokens` 上限 1024 且难票上对调 MAWB/HAWB + 凭空编签发日期 |
| 小米 `mimo-v2.6-flash` | 2026-10-08 | 与 S2 平级（中位 7.2 vs 8.1s、保真同为 99.3%、红旗同为 12 条）却 p90 45-70s 长尾，且出现过一次 HAWB_NO **静默**错填（红旗没抓）——没换来收益 |
| 火山方舟 `doubao-seed-2-1-lite` | 2026-10-08 | 开思考 97-124 秒/票，只适合当"第二只眼睛"，而那条复核流程用户当时就没接 |

两家的 id 大小写、关思考写法各家互不通用等实测细节留在 git 历史（`config.py` 注释被删的那几段）。要临时试清单里的别的模型：`VLM_MODEL` 直接写模型 id，`resolve_model` 对未知键原样透传（走默认端点与 `MODELSCOPE_API_KEY`，拿不到预设的 base_url/密钥/extra_body，正式接仍需回到这张表）。

- **主单链单独一个开关** `MASTER_VLM_MODEL`，默认 `qwen38-flash-bailian`。理由：主单输入是几百字符纯文本、没有票面图，同一条主单 S2 花 97.8 秒只取到 2/36 列，qwen 7 秒取到 17/36。**别拿分单横评去推主单**。
- 换渠道的两种方式：审核台顶栏下拉热切（管理员）/ 改 `.env` 重启。缺密钥会在解析时直接报"渠道缺密钥"，**不静默回退**。
- 纯文本模型（`VLM_VISION=0`）机制保留但不推荐：它收到图片会把票面**编**成别的内容。扫描件会明确报错，电子单/文字层 PDF 可直读。
- 超时策略：`VLM_TIMEOUT=300`，超时只重试 `VLM_TIMEOUT_TRIES=2` 次（慢模型重跑还是五分钟，连撞三次只是把人钉在等待上），其他错误按 `VLM_RETRIES=3` 退避。
- 每个预设必须带 `max_tokens` 下限：实测有单次推理烧掉 19309 输出 token 的票，8192 被掐死 → content 空 → 连败三次。

## 6. 公司系统 j9 AMS 对接（唯一会写外部数据的地方）

六个路径，主单/分单各三：一读两写（**2026-10-09 文档改版**，末尾斜杠是契约的一部分）：
`/api/v1/j9/hawb`（读分单行）、`/hawb2`（**暂存**，恒落 `SEND_STATUS=0`）、`/hawb3`（**提交发送**，落 1）；
`/api/v1/j9/mawb/`（读主单）、`/mawb2/`（暂存）、`/mawb3/`（提交发送）。
两把 key 互不通用：`COMPANY_MAWB_KEY` 只能调 mawb 组、`COMPANY_HAWB_KEY` 只能调 hawb 组，串了 403。

> ⚠️ 改版前 `2` 就是"提交"。**我们 1.7.0 及之前所有标着"已提交"的票，其实都落在公司状态 0（暂存），
> 外围程序一条都不会取走**——1.8.0 把提交口挪到 `3`。历史那批需要人工到公司页面补点「提交发送」，
> 或改完再提交一次（状态 0 允许覆盖，所以能重发）。

五条硬规矩（都在 `company_api.py`，都有用例）：

1. **先读后写**：写之前先读回那一行，读不到就拒（不能凭本地数据猜公司侧状态）。
2. **SEND_STATUS 闸门只认 0**：`1 已提交发送（还没发出去）`、`2 外围已发送成功` 两档公司都回 400「已提交，不能更新」，本地先拦下、一个写请求都不发。从前放行 2 是拿旧文档读的，等于允许去覆盖一条已发成功的记录。界面措辞跟着字典改（`0 公司暂存（未发送）/ 1 已提交发送·等外围 / 2 公司已发送成功（锁定）`）——从前把 1 写成"已发送"会让人以为发出去了，把 2 写成"已改·待重发"会诱导人去改锁死的行。
3. **整表写回 + 全字段都要在**：没给的列会被写成 NULL，所以读回来的原值要一起带上；IT 2026-10-09 又要求**列面一列不许缺**，没值的发 `null`（`HAWB_SUBMIT_COLS` 由 `fieldspec.DESK_FIELDS` 推出来，不抄第二份表）。空数字格必须发 `null` 而不是 `""`——空串会被公司判「PIECES 必须为整数」整条退回。
4. **税号统一进 EORI**：公司列面**没有税号格**（主单 36 列、分单提交体 35 列），IT 定案所有税号（USCI/CNPJ/RFC/GST/VAT）填进同主体的 `*_INFO_EORI`；同主体既有 EORI 又有 VAT 时**两个都留，用 `" / "` 拼在一格**。`codes.merge_ids()` 先拆再拼（暂存能反复写，不拆每写一次就多挂一段）。分隔符**必须带空格**：CNPJ 自己印成 `07.454.234/0001-10`，裸斜杠会把一个号码拆成两段（有用例钉住）。v1.8.0 只是提交前拼一下，**v1.12.0 起我方列面也没有税号格了**（40 → 38），号从模型手里那一步就落在 EORI。形态判据两边不同口径，别抄来抄去：主单侧按形状比（`_eori_cell_ok`），分单侧只报四条（与电话同值 / 混进标签 / CN 不是 18 位 / 短于 8 位），**不按形状拦**——英国 VAT 常是 9 位纯数字，按形状拦会把对的挡掉（`_id_cell_warns` 的 docstring 记着这条理由）。
5. **幂等锁** `GUARD_TTL = 90`：同键同内容 90 秒内不重复写（`output/submit_guard/`，一锁一文件）。**接公司暂存时这条要分开**：暂存与提交内容相同是常态，共用一把锁会让"暂存完紧接着提交"的第二次被当连点吞掉。

限流与重试：IT 文档写每把 key 10 次/秒、200 次/分钟、3600 次/小时，本地默认 `J9_RATE_PER_SEC=8` 留两成余量；读 10s / 写 20s 超时；429/5xx/连不上退避重试 `J9_RETRIES=3`，**400 业务错不重试**。`COMPANY_API_MODE=mock` 时只回本机回执不外发（默认，回归与端到端验证都靠它）。地址必须带端口：`http://j9aiaeapi.justrightlog.com:18080`（80 端口是这台服务器上的别的服务）。

公网是 http 明文，所以两把 key 按"可轮换"对待。

## 7. 审核台前端（形态③，日常主入口）

- **零构建**：`logic.js` 装纯逻辑（全局 `L`，尾部一行 `module.exports` 只为让 node 能读），`desk.js` 只碰 DOM。`index.html` 里 logic.js 必须排在 desk.js 前面（有断言）。
- **子路径自适应**：`BASE = location.pathname.replace(/\/(index\.html)?$/, "")`，所以挂在 `/hawb/` 下和根路径下都能用；静态资源走 `/web/{asset}`，`no-store`。
- **两个视图 + 一张统计窗口**：核对工作台 / 今日台账（`/day`：**分单与主单合一张表**按时间排，行上带 `kind`，主单行多显示"取到几列/36"；每行一个「作废」软开关——只往 `voided.json` 写一个戳，**提交台账、暂存、归档原件与索引一律不动**，作废的行不进台账计数也不进正确率，勾「只看作废」能翻回来恢复）；**统计**（`/stats`，见 §9 的口径）不占页面，是顶栏那颗按钮开出来的一张浮层窗口（`#statsWin`，与「账号管理」同一套 `.gate` 形状）——从前它是压在页面最下面的一节，永远比核对区矮半截，要滚到底才看得见，也没法一边开着票一边看数。**入口与接口都只对管理员**（2026-10-09 业主定案；作废不是：登录就能点 + 二次确认 + 留痕）。左侧 48px 状态窄轨 + 置顶待办条 + 底部常驻操作条。
- **票面浏览演进（重要）**：早期把 PDF 交给浏览器内嵌阅读器，结果 ① Chrome 的缩略图侧栏吃掉近一半宽度；② 窄高栏里 `view=Fit` 与 `view=FitH` 算出**同一个缩放**，按钮点了没反应；③ Edge 完全不理 `navpanes=0`，侧栏关不掉。v1.0.3 起**票面一律走我们自己的 `/render` 页图**（服务端 pymupdf 按页转 PNG，页数从响应头 `X-Ticket-Pages` 拿），v1.0.4 加"按住拖动"，v1.0.5 加"滚轮缩放"。
  - 缩放算式全在 `logic.js`：`wholePagePct`（整页所需图宽，占栏宽百分数）、`maxZoomPct`（不许超过渲染像素，A4@scale2 在 675px 栏位 = 176% 见底）、`zoomStep`（滚轮乘法步进 ±15%，25–400%）、`zoomAnchor`（钉住光标下那一处）、`canPan`（内容真超出才给抓手）。
  - 两条反复强调的判据：**不给"看着能拖其实拖不动"的假抓手**；只剩一档的按钮就藏掉。
  - 监听滚轮必须 `{passive: false}`，否则 `preventDefault` 被忽略、滚轮还是去滚整页。
  - 只有拿不到归档（那张票早于「上传一律落盘」上线，或归档被清理过）才退回浏览器阅读器，那条路径保留三档循环（`pdfBox`/`viewCycle`/`firstView`）。
- **点字段定位票面**：点右侧字段名 → `/layout/{stem}` 取 L1 行 bbox → `/render` 页图打底 → 高亮 + 滚到那一行。**放不放大、放多大是各人的手感**（v1.4.0，用户要的开关）：定位那条工具条里有「定位时：自动放大 / 固定倍数 / 不放大」+ 一个百分比框，偏好存本机 localStorage（`hawb.review.locate.zoom`，默认 `auto`）——**只存内存不算开关**（刷新就回默认），**只藏按钮也不算**（"不放大"要把上一次的倍数收回到 100%，否则只挡得住第一次）。倍数与上限的算式在 `logic.js`：`autoZoomPct`（命中行约占窗格 1/3，100–500%）、`locateZoom`（三档合成一个倍数，`null`=不放大；`fixed` 与 `auto` 都不许超过 `maxZoomPct`，填超了落到上限并 toast 说清实际用了多少，同时把上限写进输入框的 `max`）。
- **两档"存"分开**（v1.2.0 定，v1.9.0 改了第一档的去向）：**暂存**（按钮「暂存到公司」，`/stage`、主单 `/master/stage`）= ① 存到本机服务器（留痕：谁改了哪几列，同事检索得到）+ ② 在 j9 那边占位（`hawb2/mawb2`，落状态 0，可反复改、外围不取）；**提交**（`/submit`）= 走 `hawb3/mawb3` 提交发送，落状态 1，**从此公司两侧都改不动**。三条边界都有用例：mock 模式下一个公司请求都不发（回归与端到端靠这条）；暂存永远不许碰提交发送口；公司那一发失败**不回滚本机那份**，只把原因随回执带回去（`stageMsg` 说"已暂存…；公司暂存失败：…"），否则人以为白点了又点一次。缺主/分单号的票仍允许存本机（公司按号定位，缺号连行都找不到），此时回 `skipped` 并写明原因。幂等锁按档分开（键带 `#send`/`#stage`）——同内容"先暂存再提交"是常态，共用一把锁会把提交当连点吞掉，票就永远停在状态 0。本机 localStorage 那块仍叫「本机未保存的编辑」。打开别人暂存的票时服务器那份赢，本机未存的改动不删但点名（`L.stagedMerge`）。
- **草稿**：编辑存本机 localStorage（`L.draftMerge/draftPut`），提交成功后仍可回看；解析值与草稿原值不一致的列才算"打架"，不无脑覆盖。
- **宽窄与框高都交给人（v1.5.0，值框的宽 v1.6.0，一个斜角自由拖 v1.7.0）**：四样手感都能自定义，全部存本机 localStorage（各人屏幕不一样，不该互相将就）——
  ① 长文本格拖出来的高度：`L.fieldHeight(记录值, 内容高)`，**记过那一列就以拖的为准**，`autoGrow` 不再按内容重设它（从前它每下输入都重撑，拖完一打字就弹回去，"能拖"等于"不能自定义"）；原生 resize 不触发任何事件，只能 `pointerdown` 记高、`pointerup` 比对；恢复出口是待办条/主单工具条上的「框高恢复（N）」槽位（`.fhslot`，拖完当场刷出来，不重画整表以免弄丢正在编辑那格的光标）——**不用双击**，双击在文本框里是选词。
  ② 票面栏↔字段栏那道缝（`#gripView`，网格多出一条 10px 轨）：存 `--vw`（票面栏占整行的**百分数**），两侧各留 260px 底线。
  ③ 字段名列宽（表头右边界那道 `#gripCol`）：存 `--colK` 像素。
  ④ **值格右边界那道 `.edg`**（v1.6.0，`edgeGripHtml()` 画在每一格上，分单表与主单表两处模板都要接）：往右拉 = 值这一列更宽，宽度是从票面栏那头扣的，所以它写的就是 ② 那份偏好（`LS.split` / `--vw`，共用 `deskGeom()`+`saveDeskShare()`，两个入口一份数）。算式 `L.boxWidthPct(票面宽, 右拉像素, 整行宽, 底线)`——**方向最容易反**（反了就是"想拉宽结果更窄"），单独一个函数单独一条用例。堆叠态（≤1460px）没有另一侧可挤，`.edg` 与 `#gripView` 一起 `display:none`——留着就是按住不动的假抓手。三道把手都可键盘方向键调，都带 `role="separator"`。
  ⑤ **一个斜角同时管宽高（v1.7.0，用户："可以自由拖拽改变大小的"）**：短字段从前是 `<input>`，而**原生 resize 只长在 textarea 上**，所以值列一律换成 `rows="1"` 的 textarea（`.one` 标单行，`blockEnter` 挡住回车——这个值原样写进公司系统，换行进去就是脏数据；数字列留住 `inputmode="decimal"`）。斜角拖的看起来是"这一格"，但值是一整列：`pointerup` 时高按列记进 `LS.fieldH`，**宽那一下换算成整列份额**（走 ④ 同一份偏好）并**把 inline 宽擦掉**（不擦那一格从此钉在自己的宽度上，下次调列宽调不到它）。
  ⑥ **高度上限分两种人说（v1.7.0）**：CSS 的 `max-height` 会**连人拖的一起卡住**（原生 resize 尊重它），所以渲染层只留 900px 那道"别把页面撑爆"的硬边界，"没人拖过就按内容撑"的 320 上限挪进 `L.fieldHeight` 的自动那一支。
  ⑦ 两处只有浏览器能发现的（v1.7.0 实测）：状态列的宽从前只写 `td.s{width:120px}`，fixed 表格不认 ⇒ 它和值列**平分剩余空间**，值框白窄一半（316→529px，修在 `th.scol`）；`th.kcol` 为安置表头把手写过 `position:relative`，把全局 `th` 的 `sticky` 顶掉 ⇒ 表头第一格跟着内容滚走、右边两格还粘着（sticky 本身就是定位上下文，不用另写）。

- 主单视图借同一对面板，但那一栏是"资料文本"不是票面图，点字段不能定位——界面上写明了。

## 8. 登录、账号与安全边界

- 登录是**唯一**门禁（`auth.py`）：pbkdf2 口令哈希 + HMAC 签名会话 Cookie；`users.json` 存哈希与 secret。历史上的 `HTTP_API_KEY`/`X-API-Key` 已连根删除。
- 三角色：`admin`（可切模型、管账号、看统计）/ `reviewer` 制单员（上传、核对、暂存、提交）/ `inputter` 录入员（读别人的暂存、复核、提交）。`require_web` / `require_admin` 只认会话；业务口**只有统计这一处**按角色分档——`/stats` 与 `/stats/export` 都是 `require_admin`（2026-10-09 业主定案："统计只给管理员"）。藏按钮不算门：导出那条链接是同一份数的另一种拿法，两处都得挡（`test_stats_is_admin_only_for_page_and_export`）。其余口仍不分档——现有角色就这三个，收全部角色的门等于没有门（早年那道"只让录入员和管理员用检索"的守卫随 2026-09-26 的并入删掉了，别再按它理解权限）。
- 发送公司前**三道门**（`/submit`，主单 `/master/submit` 同构）：号要齐 → 红旗按当前值重算并逐条确认 → **没有"录入员复核过的暂存记录"就要多点一次确认**，并留痕 `no_inputter_review`。用户定案是"制单员仍可直发，但要额外确认并留痕"：留痕不是为了拦人，是为了以后能算出"跳过复核直接发的那批错得多不多"。
- 首启种下 `admin/admin123` + 8 位制单员（种子口令为空，登不进）+ 3 位录入员。**上线第一件事：改 admin 口令并给制单员下发口令**。
- 这件事不再只写在文档里：`auth.admin_still_uses_seed_password()` + `/api/me` 的 `admin_pw_default` 会让顶栏给管理员亮一颗「口令未改」（点了直接进账号管理，改完当场灭）。**故意不放 `/health`**——那个端点免登录，等于站在门外告诉对方管理员还是默认口令；也不发给制单员（改不了的人不必被推，少一处出现少一处泄露面）。
- 密钥与本机文件：`.env`、`users.json`、`output/`、`input/`、`_quarantine_20260920/`、IT 那份带真 key 的《AMS录入接口调用说明》全在 `.gitignore` 里，并有 `tests/test_gitignore.py` 拿 `git check-ignore` 逐个问一遍（源码文件被误挡也会红——部署清单取自 `git ls-files`）。
- 提交动作只由人点。回传失败的原因会带票号落到服务日志（`journalctl -u hawb-desk` 可查），不只在响应里一闪而过。

## 10. 测试体系（704 项，零 pytest）

- 入口 `python -X utf8 tests/run_tests.py [过滤词]`，自定义 runner，44 个 `tests/test_*.py` 自动发现。

## 15. 踩过的坑（这一节最值钱，改代码前扫一眼）

1. **闸门自己也要被验证**。`sync.sh` 的回归闸门曾是空的（`| tail -3` 让退出码变成 `tail` 的 0），"部署成功"却没人跑过测试。同类：`tar` 不删远端已删文件 → 线上留孤儿模块。
2. **Windows 控制台是 cp936**。把 stdout 强改 UTF-8 不崩，但用户看到的是一整屏乱码；只设 `errors="replace"`。`.bat` 是 GBK+CRLF，**绝不能用按 UTF-8 读写的编辑器改**（有断言要求"仍能按 GBK 解码"）。
3. **别用 heredoc 写含中文/反斜杠的源码**：`\b` 会落成退格符，正则照旧编译通过却谁也匹配不上。
4. **`git commit -m "..."` 里别放反引号**：双引号内的 `` ` ` `` 会被 bash 当命令替换执行，提交照样成功但那半句没了。
5. **ssh 远端命令的退出码会被管道最后一条吞掉**，本地 `pipefail` 管不到远端 shell；要判成败就 `; echo \$?` 带回来。
6. **真实票名带 U+00A0 不间断空格**（`016-82445790\xa0分单`），手敲普通空格去调 `/render` 会 404；票面里的连字符常是 U+2010，重音字母会拆码位。
7. **改 `.py` 必须重启服务**，而重启会踢掉在线会话；css/js/文档用 `--no-restart`。出现过"服务端跑的是旧进程、新功能像坏了"的静默失效，`/health` 的 `stale_files` 就是为此存在。
8. **阅读器的地址参数两家不通用**：Chrome 认 `navpanes=0`，Edge 完全不认（只认 `toolbar=0`）。凡是把表现交给第三方内嵌组件，就要按"最保守那家"设计，或干脆自己渲染。
9. **界面控件点了必须有反馈**。"两个选项在某种版式下算出同一个结果"就是死按钮（`Fit`/`FitH` 撞车、抓手残留），判据要写进测试。
10. **口径别替用户放大**：USCI 可以填 EORI，不等于"什么号都能塞 EORI"；主单税号非 USCI 的那类要问 IT，不猜。
11. **内联样式的最大源头不在 HTML，在 JS 的模板字符串里**。盘点时只数 `index.html` 会数出 8 处，实际 `desk.js` 里还有 32 处——它们不吃令牌、在样式表里搜不到，去卡片化/换色板那天必然漏。守卫要扫 `desk.js`，并允许"当场算出来的值"留在行内（票面 bbox 的百分比、台账的列宽比例）。
12. **给 sticky 容器做浮层，要连层叠上下文一起想**。`position:sticky` 自成层叠上下文：窄轨展开列表写 `z-index:70` 也只在这个上下文里比，压不过 DOM 更后的 `#view`/`#main`。当时没撞上是靠"列表 286px 宽 < 栏位起点 340px"侥幸，窗口一窄就露馅。层级要给在容器自己身上（`.rail{z-index:var(--z-rail)}`）。同理 `--z-toast` 必须高于 `--z-gate`：那条"登录已过期"正是和遮罩同时弹的。
13. **对比度按角色算，不按颜色算**。同一种绿，当状态点 ≥3.0 就够，当 11px 小字要 ≥4.5——所以 `--c-ok`（填充）和 `--c-ok-text`（文字）是两个令牌，别为了少写一行而共用。算的时候还要按"这个字实际会压在什么底上"配对：去卡片化会把文字从白底搬到页面底，那一档差 0.5~0.7。
14. **会随宽度变高的高度不能写死**。顶栏在 1920/1500/1200 三档实测是 97/96/135px，而样式里三处 sticky top 抄的是 64px、令牌里写的是 54px——1200 那一档差 81px，票面栏会顶进顶栏底下。`--hdh`/`--todoH` 一律由 `measureChrome()` 写回，`ResizeObserver` 负责重测。
15. **改 JS 模板里的 HTML 属性时盯紧引号嵌套**。`"<b style='color:#8c4a17'>"` 换成 `class="svc-warn"` 会把双引号撞进双引号字符串里，整份 `desk.js` 语法报废——这条被"生成的 JS 要能被 node 解析"那类用例当场抓住，不是靠肉眼。
16. **写盘的用例必须指开每一个目录**。一条提交用例漏指 `OUTPUT_RAW_DIR`，就往运维机的真 `output/raw` 落了一份假 L2，后面三条用例读到它、报出凭空的红旗。本机**查不出来**（上一次跑已经留了同名文件，前后一致），是部署时的回归闸门在干净的 VM 上抓到的——所以入口现在比 `output/` 的文件清单，不止比 `.env`。加新用例时先问一句：这条链路上有几个目录？
17. **删掉一个开关，要连"读它的那条分支"一起删**。去掉「落盘留档」复选框后，`desk.js` 里 `if (t.file && !t.save)` 会恒真（`t.save` 再没人赋值），图票于是永远拿浏览器里的 Blob 当底图、`LOC.remote` 判错——**功能表面正常，定位模式悄悄退化**。守卫断言的是 `t.save` 这个标识符不许再出现，而不是断言那个分支还在。
18. **输入校验别挂在可替换的单例上**。把 `server._safe_stem` 改成转调 `store.safe_stem` 逻辑上更对（写文件与读文件同一条规则），但测试会把 `server.store` 整个换成桩，于是 10 条读票面的用例一起报错"桩上没有这个方法"。改成模块级绑定 `_safe_stem = store.safe_stem`：判定只有一份，换桩也换不掉它。
19. **守卫要断言"带条件的写法"，不是断言字符串存在**。前端把"未经录入员复核"的确认写成无条件 `acked_no_review = true`，那条 `assert "acked_no_review" in js` 照样绿——是拿变异验证（把它真的改成无条件）才发现的。同类：注释里写出 `fetch(` 会被 BASE 前缀守卫当调用点抓下来，说明文字也得避开被扫的那个子串。
20. **两个百分比不是一回事**。`acc_field`（模型读得准不准）与 `acc_after_review`（复核之后人还剩多少活）共用分母、含义相反方向；拿去回答"能不能直接对接平台"的必须是后者。同理"没暂存记录"的票要把改动记到制单员档而不是记 0——记 0 会系统性抬高正确率，而**抬高方向的误判会答应下本来不该接的对接**。
21. **`release.sh` 要求版本号是"未提交"的状态**。它自己做 `sed 改号 → git add config.py → git commit`；如果发版前已经手工把版本号提交过（2026-10-09 就这么撞了一次），它那句 commit 变成"nothing to commit"，而脚本是 `set -e` —— **就地中断，后面的打 tag、推服务器、推 GitHub 一步都没做**，退出码却容易让人以为发完了。所以：要么把版本号留给脚本去改，要么中断后手工补齐这三步并自己核 `/health` 与远端 tag。
22. **前端用例比的是 JSON 的值，不是类型——值的类型要单独钉**。服务器暂存记录里 `WEIGHT` 存成了 `1234.5`（浮点）、`PIECES` 存成了 `77`（整数）：那是 `store.field_diff` 归一后的样子。`L.stagedMerge` 把这同一份值原样塞进 `airE`，核对页渲染到 `l3.trim()` 就抛 `l3.trim is not a function`，**整页字段一个都不出来，屏幕上是"上传分单后在这里逐字段核对"**——像没打开票，其实是被异常打断在半路。node 那条用例当时全绿：`assert r["airE"] == {"PIECES": 77}` 里的 77 与 "77" 它不分。现在合并函数出口一律 `String()`，并有一条用例专门断言"值必须全是字符串"。教训 generalize 一句：**跨语言边界（Py↔JS）传的数据，形状也是一种契约**。
23. **"哪几列算改动"只允许有一份算术**。`stagedMerge` 从前自己拿 `air_model` 与 `air_final` 比字符串：45.0 与 45 一比，一列谁都没动过的值挂上了改动标记（人随即开始怀疑所有标记）。服务端早就用 `store.field_diff`（数字按数值比）算好了 `edits`，前端改成直接认它。同一条规则下主单记录补了顶层 `edits`，与分单同形——**统一的是机制，不是字段面**。
24. **指标的名字必须圈住它数的那些行**。「未经录入员复核就发出」从前把所有 `no_inputter_review` 的行一起加，于是**只暂存、压根没发**的票也进去了：数会随谁把工作停在暂存那一档而涨，而它是拿去看要不要对接平台的数。行上的标记照旧留（那是这张票自己的复核状态），合计只数 `state == "submitted"`。
25. **CSS 变量不能拿去乘 `1fr`；fixed 表格只认表头给的列宽**。给分栏写 `minmax(420px, calc(var(--vr) * 1fr))`，Chrome 判整条 `grid-template-columns` 非法、掉回自动布局：把手那一轨变成 0px，两栏再也不跟着变量变——静态用例全绿，只有量 `getBoundingClientRect()` 才看得出来。改成 `minmax(420px, var(--vw))`（百分数）就好：`var()` 替进 `minmax` 是支持的，坏的是 `calc()` 里拿变量去乘 `fr`。同一轮另一处：`table-layout:fixed` 下列宽写在 `td.k` 上不生效（量出来一直是 276px，不是我设的 366px），要写在 `th` 上。**凡是"拖了有没有反应"这类事，断言只能钉形状，生效与否必须在浏览器里量。**
26. **用户点名要"改文本框的宽度"，就别回给他"其实是这一列的宽度"**（2026-10-09 连着被推回两次，第二次原话"我只想单纯的可以改变文本框的宽度"）。效果上两者是一回事——fixed 表格里一格宽了整列就宽了，而这一列的宽又是"整行减去票面栏"；但**入口必须画在他手指指着的那个东西上**，于是每格右边界一道 `.edg`，拖它 = 值列宽 = 从票面栏扣，写的是分栏那道把手同一份偏好。顺带一条否掉"用原生 `resize:both` 就好"的硬事实：**`resize` 对 `<input>` 不生效**，值列里一半是 input，只让长文本能拖宽比都不能拖更让人以为坏了。同一类坑还有"底线"：挤到 `minmax(420px, …)` 那一档时票面栏不再让路，把手就该停住（实测停在 420px、`#main` 不出横向滚动条），而堆叠态压根没有另一侧可挤，就把把手整条藏掉——按住不动的假抓手比没有把手更糟。
27. **同一件事第三次栽在"fixed 表格只认表头那一行"上**：状态列的宽从前只写 `td.s{width:120px}`，Chrome 直接不认 ⇒ 表头那格成了"没给宽度的自动列"，于是它和值列**平分剩余空间**，值框长期只有应有宽度的一半（实测 316px，修到 529px；拖 120px 只长 60px 就是它的影子症状）。同一轮另一处：`th.kcol` 为了让表头把手贴住右边界写了 `position:relative`，把全局 `th{position:sticky}` 顶掉 ⇒ 字段表滚起来"字段"那一格跟着走、右边两格还粘着。**sticky 本身就是定位上下文，absolute 的子元素照样贴得住**，别另写 relative。⇒ 布局上的每一条声明都要问一句"生效的那一层是哪一层"，而答案只有浏览器量得出来。
28. **CSS 上限会连原生拖拽一起卡住**：`td.v textarea{max-height:320px}` 本意是"自动撑别撑爆卡片"，但原生 `resize` 尊重 `max-height` ⇒ 人只能拖到 320px，"自由拖拽"就半废。改法是把两种人说清：渲染层留 900px 那道硬边界，"没人拖过就按内容撑"的上限进 `L.fieldHeight` 的自动那一支（320）。同类判断：**一条约束如果同时管着"系统自己做的"和"人主动做的"两件事，就得拆开写。**
29. **外部契约最阴的一种改动：端点没变、含义翻了面**。IT 2026-10-09 的改版把 `2` 从"提交"改成"暂存"、新加的 `3` 才是提交发送——我们代码一行不报错、回归全绿，而**所有标着"提交成功"的票在公司侧都是状态 0，外围程序一条都不会取走**。⇒ 拿到新版接口文档，要问的不是"路径还在不在"，而是"每个写口落什么状态、谁能覆盖谁、锁在哪一档"。这类语义只能有用例钉住：现在 `test_*_goes_to_the_send_endpoint` 钉住走 `3`，闸门"只认 0"也各有用例（放行 2 的那条是拿旧文档写的，等于允许去覆盖一条已发成功的记录）。附带一条：j9 假桩被四个测试文件各抄一份，端点一改同时炸八条 —— **判据（哪条路径算写口、回执长什么样）收敛进 `tests/j9_fake.py` 一处**。
30. **拼串的分隔符要挑"数据里不会出现的那个"**：税号统一进 EORI 后，同主体两个号要拼在一格，最先想到的 `" / "` 正好撞上巴西 CNPJ 自己的斜杠（`07.454.234/0001-10`）——裸斜杠一切，一个号码变两段，再拼回去就永久坏了。定成**两侧必须带空格的 `" / "`**，并留一条用例拿 CNPJ 专门试（把正则改成允许裸斜杠，那条就红）。同理，凡是"能反复执行"的合并（暂存会反复写同一格）必须**先拆再拼**，否则每写一次多挂一段。
31. **全局开关"能不能生效"要由被开关的那张表自己说，不能让界面猜**（v1.10.0 思考档）。一个 `MODEL_THINKING` 管两条链、管所有渠道，看着省事，代价是**有的渠道压根不吃这个参数**：官方书生连 `extra_body` 都不收，多塞一个 `enable_thinking` 直接 400——整票解析当场失败。所以生效面写成预设里的声明（`thinking.param`），`model_extra_body()`、`/models` 的 supported、下拉的置灰三处都从它派生；把判据挪进界面或前端"看着像支持就发"，下一个不接受该参数的渠道就是线上一片红。同类判断：**开关越全局，越要让每个被它管的对象自己表态。**
32. **导入期就求值的配置，函数定义顺序是硬约束；断言里读活的配置值，要在钉住它的那个上下文里取值**（同一轮两处）。① `resolve_model()` 在 `config` 导入时就被 `_MODEL_INFO = resolve_model(...)` 跑一次，而它的标签要用 `thinking()` —— 把 `MODEL_THINKING`/`thinking` 写在下面一行，模块直接 `NameError` 起不来（跑测试才发现，比跑服务才发现早不了多少，但报错完全指不到"顺序"这件事上）。② `test_api_clients_are_bounded…` 从前在 `with _ModelState()` **退出之后**才拿 `config.vlm_base_url()` 去比三个客户端：退出那一刻选择已恢复成 .env 的值，于是这条用例变成"这台机器的 .env 是不是 S2"的探测器——本机 2026-10-08 切到 qwen 后它必假炸，而 VM 上恰好还是 S2，所以全绿了两年。**"跟着环境走的断言"要先把环境里的值取进局部变量再比。**
33. **"本机全绿"不等于"这个包是绿的"：一条没锚定的 .gitignore 规则能吞掉测试夹具吞几个月**（v1.10.1）。`input/` 与 `output/` 少了前导斜杠，git 就把**任意层级**的同名目录一起吞了 —— `tests/fixtures/l3/input/` 那 41 份 L3 基线从没进过 Git、没进过 GitHub、不在 `git archive` 打的部署包里；本机跑回归照样绿，因为文件就在盘上。第一次现形是"把包解到空目录跑一遍回归"，报的是"L3 回归夹具只剩 0 份"。两条 git 事实要记：① **忽略规则对已入库的文件不生效**，所以拿 `tests/fixtures/l3/input/1_dsv.json` 去问 `git check-ignore` 永远得到"没被忽略"——要探规则，得探一个**未跟踪**的同目录路径；② 规则层问不出来，就问索引：`git ls-files` 与盘上文件数一比，"没被 add 进来"当场现形（这条只在开发机与发版前的本地回归上有意义，服务器那份代码没有 .git）。⇒ **交付物要按"解到空目录能不能自跑"来验，别拿开发机的既有状态当证据。**
34. **回归不许读运维机上的偏好**（v1.10.2，同族第三次）。线上有人把思考档拨到"开"（写进生产 `.env` 的 `MODEL_THINKING=1`），当天部署时服务器上 4 条用例齐红、发版被 sync 的回归闸门拦下（代码已推、服务没重启，线上仍是旧版——闸门行为是对的，红的是用例）。根因和 2026-10-08 那次"回归写真 .env"、这次"往真 output/master 落一份"是同一件事：**config 在导入期读的每一个 `os.getenv`，要么在 `run_tests.py` 入口钉成固定值，要么由用例自己钉**，否则"这台机器现在怎么配的"会变成用例的一部分，而它在任何一台机器上都可能变。钉法照旧靠 `load_dotenv` 默认不覆盖进程环境这一条性质（入口先 `os.environ[...] = ...` 再 import config）。**运维动作能让回归变红，就等于运维动作能挡住发版**——这两件事都不该发生。
35. **`[hidden]` 会被任何一条 `display` 规则顶掉，而"逐个元素补规则"的清单迟早漏一个**（v1.10.3，同一族第三次）。`.wrap{display:grid}` 让今日台账里 `$("#wrap").hidden = true` 完全不起作用：那一屏还占着 956px，台账表整张被顶到首屏之外，用户看到的是"上面一堆分单解析、底下才是台账"。前两次分别是 `.pvtools{display:flex}`（工具栏该收时照样亮）和 `.f{display:flex}`（模型下拉收不起来），当时的修法都是就地补一条 `.xxx[hidden]{display:none}` —— 于是清单散在样式表里六处，而**回归那条守卫查的正是这份手抄清单**（只列了三个元素），所以 #wrap 漏了也没人响。现在：一条全局 `[hidden]{display:none !important}` 兜住，六处逐元素规则删掉，守卫改成从 `desk.js` 里把用 `.hidden` 开合的元素**全捞出来**逐个查兜底。⇒ **凡是"靠人记得加一个"的守卫，都要改成"从代码里捞"**；判据同 §15 第 25/27 条：这类事静态检查看不出来，只能在浏览器里量 `getBoundingClientRect()`。
36. **"把这条删掉"先问一句：他要的是"别烦我"还是"没发生过"**（v1.11.0）。台账要删除键，真做成删文件的话会连带抹掉两样不可再生的东西：`submitted.json` 里那条"这张票回传过公司、谁签的字"，和 `archive/<stem>/` 里的原件本身——出事时这两样就是全部证据。所以做成**软闸门**：单独一本 `voided.json` 只记"谁、何时把这一行收起来了"，台账与统计都不再算它，但一行数据都不删，随时能恢复；配二次确认与留痕，**登录就能点**（掐成仅管理员，制单员的反应不是不提，而是干脆不删、让测试数据永远留在正确率里）。另外一条技术事实值得记：**台账那一行的骨架是质检记录，不是提交台账**——`ticket_rows` 从 `output/qc/*.json` 起行，再 join 台账与暂存，所以"只删提交记录"根本不会让行消失，问清楚"删什么"比问"能不能删"更要紧。同一轮把主单也接进台账：主单缓存是**按主单号覆盖存的一份**，"哪天经手的"只能取最后一次动过的时间，重算会把这张主单挪到当天——这是数据的形状，不是 bug，但要在设计时说在前头。
37. **删一列最危险的地方不在代码里，在"已经落盘的老数据"里**（v1.12.0）。列面 40→38 之后，代码路径全改完了、回归全绿，而 `--recheck` 那一行 `raw = {k: stored.get(k,"") for k in TARGET_KEYS_OUT}` 还在按新列面"修剪"老结果：老票的号只存在那一列里（当年的口径就是单独立一列，地址串是干净的），修剪完再重算 L3，号在 raw 和 air 里**同时消失**，而下一次提交给公司的 EORI 就是空的。这条不花一分钱就能复现（recheck 不调模型），但只有在**拿真台账副本跑一遍**时才看得见——夹具里那 41 份 L2 全是 38 列时代的。⇒ 删列的清单要多两条：① 找一遍"谁在按列面重建老记录"（recheck / 导出 / 重算），② 迁移路径要有用例（老键进新格），并且**幂等**：跑两遍的结果必须和跑一遍一样，运维手滑不该弄坏数据。同一轮的另一条：**形状判据要跟着落点放宽**——一格现在装的是各国自己的税号，英国 VAT 就是 9 位纯数字，把主单侧那条按形状比的正则照抄过分单侧，基线里立刻多出一格假红旗；判据的松紧属于口径，不属于"能复用就复用"。

44. **收纳出一层新容器，就多出一层"谁盖住谁"——叠着开的两张同 z-index 遮罩，静态用例一条都不会红**（v1.17.0）。把六颗入口收进「设置」浮层之后，从浮层里点「解析正确率」：统计那张确实开了，设置那张也还开着，两者都是 `.gate` 全屏遮罩、同一个 `z-index:80`，而**设置写在 DOM 里更靠后，于是它盖在新窗口上面**——人点了统计，屏幕上仍是设置，这比"按钮坏了"更像"系统坏了"。浏览器里一眼看见，562 条静态契约一条不红：它们各自只看一张窗口，从没有"同时看两层"这个视角。⇒ ① 从一层里开另一层，**先把这一层收掉**（统一走 `openGate(id)`，别在每颗按钮里各摆一次 `.hidden`，那样加一颗就漏一颗）；② 收纳之后凡是"关掉一层"都要追问一句**焦点落在谁身上**——子窗口的入口（统计/清理/账号）此刻藏在刚收起的设置里，`focus()` 给它等于丢失，按 `offsetParent` 退回顶栏那颗看得见的「设置」。相关：第 43 条、第 39 条

46. **「这一天」是一页数据最容易被误解的那个词——它认哪个字段，要按人问的那句话定，不是按记录里现成的字段名定**（v1.17.1）。今日归档一直用 `processed_at`，因为那张表最初是"今天读了哪些票"；可制单员提交完回来找的是**"今天发了哪些票"**，两句里的"今天"不是同一个日子。数据全在、接口全 200、页面没错，人却认定票丢了。⇒ ① 一页按天筛之前先问"这一天里做过哪些事"，凡是**动过就算**的语义都要把每个动作的时间并进来（这里加了提交台账那一次），别让只有一个时间戳的字段替业务定义"今天"；② 收进第二个日期时必须同时写一条**反向闸门**（解析日与提交日中间那天必须为空），否则很容易把"哪天都算"当成"两个日期都算"交上去；③ 口径改了要写在脸上（那颗日期的 `title` + 行上保留两个时间），不然下一个人还是会把"今天没行"读成"今天没票"。**同一条里还揪出一个跑了几个月的假事实**：注释与上一版提交说明都写着"VM 跑 UTC，北京早上八点前的票会落在前一天"，实测 `processed_at` == 文件 mtime == journal 时间（都是 07:26 本地）——`datetime.now()` 从来就是本地时钟。写进注释的时区/环境类断言，要么当场量一次，要么别写：下一个人会拿它当依据做判断（这次它被拿去做"日期只能由服务端算"的论证，而那条论证其实另有真理由：台账是本机的、不共享）。相关：第 42 条（两台机器各记各的账）、第 43 条（静态契约看不见界面算的数）

47. **硬门的"已清"只许有一本账：前端每加一条"我觉得这条不用人确认"，就得问一句服务端认不认**（v1.17.2，现场是 `NO.A-NGB2609026B` 提交被拒而界面写着 红旗 0）。提交那道门是 `left = [f for f in recompute_flags(...) if f not in acked_flags]`——它唯一的账本是人点过确认那串字符串。而前端 `effectiveFlags` 里有三条"视为已清"：① 人点过确认（两边同源，对）；② 缺的号补上了（**服务端重算用的是当前值，本来就不再报它**，所以也同源，对）；③ 税号那格已自动摘掉标签（**只有前端知道**，错）。第三条把旗从界面上拿掉、不进 `acked_flags`，于是它既看不见也点不到——整段核对那颗同样只收 `effectiveFlags`，改值再改回来又会被 `setEdit` 清掉确认，绕不过去。⇒ 判据："这条旗还算不算数"这个问题，凡是前端自己回答、而服务端不认的，一律是死旗；要么两边同源（都按当前值重算），要么就别藏、让人点一次。同一族的另一半是**报错必须指名**：服务端 400 里带着 `{message, flags}`，前端只弹 `message` 就等于让人对着一个不存在的按钮发愁。现在 `t.srvFlags` 接住那份名单、并进待确认列表（也进本机草稿），这条链在改了值旧旗文案变化时同样救场（重算出的新文案本地根本没有）。**另一条测试侧教训（同一轮 3 个变异第一轮活着）**：钉"某个函数名/某个变量名在不在"是空的——把分支条件改成 `if(false)`、或换一种写法直接匹配旗面文案，断言照样绿。要钉**形状与个数**：`effectiveFlags` 里只许有两个提前退出（`ack.includes(f)` 与 `okM && okH`），多一个就是又有人替服务端做主。而"这个分支真会进"静态用例根本钉不出，只能靠浏览器端到端——这是第 43 条那一族的第九次，也是第一次明确把"静态够不着"写进用例的 docstring 里。相关：第 39 条（用例要先被改坏一次）、第 43 条、[[hawb-desk-air-only-preview]]

48. **给不可逆操作放大可见范围时，"默认那一份集合"和"一键作用范围"要各钉一颗钉子，绕过安全期那一格由服务端算**（v1.18.0）。清理面板从前只列到期的票，这轮要列全部 + 倒计时 + 每行可手动删。同一处代码有三个一顺手就会踩的地方：① `candidates()` 是**三方共用**的（面板、顶栏徽标、`run_purge.py --auto`），给它加一个"也列未到期的"开关，只要默认值写成放开，三处语义同时被改——徽标会从"有票到期该清了"变成"这台机器一共有几张票"，而它看起来仍然是一个正常数字，没人会发现口径换了；所以新开关默认关掉，并单独钉一条"默认那份名册不许混进未到期的"。② 「全选 / 全不选」原本作用在"当前过滤出来的那几张"，列表一放大它就自动变成"一键把所有票勾上、点两下抹光"；必须显式限定只翻已到期那一批。③ 绕过安静期这件事**不能让调用方自报**：`early` 由服务端比较"这张安静了多久 vs 当下窗口"算出来，两个方向都验（没满的说成满了、满了的说成提前，记的都是事实）。⇒ 通用一条：**给一个已有安全闸门加"更多入口/更多可见性"之前，先数清楚有几处在共用同一个算出来的集合，逐个钉住它该看的仍是老范围**；相关：第 41 条（自动化不许把判据压在人身上）、第 47 条（两边各判一次就是死旗）、第 39 条

49. **一条给"整页滚"写的 sticky 偏移，会跟着样式表走进每一个自己滚的浮层——第三次才想起把它写成一条闸门**（v1.18.0 前，线上 v1.17.2 用户报回）。全局 `th{position:sticky;top:var(--hdh)}` 的意图是"表头停在顶栏底下"，`--hdh` 是顶栏实测高度（这台机器 91px）。可粘附的**参照物是最近的滚动容器**，不是视口：整页滚时那正好是视口，浮层里滚的却是 `.purge-body` 自己——于是表头被往下推 91px，从容器顶掉进列表中间，上下各露出一行数据，看上去像同一行重复了三遍。同一件事此前已在 `#mstHawbBox`（2026-09-29「名下分单从 264px 左栏搬出去」那批）与 `.statsbody`（v1.3.0 统计窗口）各修过一次，两次都是"就地补一行 `th{top:0}`"，没有留下任何会拦住下一个的守卫，所以第三个带表的滚动浮层（清理面板）原样又犯了一遍。**列表短到不滚时症状不存在**——v1.17.2 那张面板只列到期的票、线上到期数为 0，所以它一直在那儿睡着；这轮把面板改成列全部票（52 行必滚），它才第一次被人看见。⇒ ① 凡是给整页写的偏移量（`--hdh`/`--stick`/`--todoH`），复用到浮层时要逐个重问"这时候参照物是谁"；② 这类坑静态审查看不出（选择器、层叠、值全都"对"），只有浏览器量得出，所以修完在浏览器里量 `thead.top - body.top`：修前 91、修后 0；③ **第三次踩同一个坑，就说明补一行不够**——用例从"点名 `.statsbody`"改成一次钉住全部三个自己滚的带表浮层，第四个再漏就红。相关：第 12 条（sticky 的层叠上下文）、第 14 条（会随宽度变高的高度不能写死）、第 27 条（同一格别写 `position:relative` 顶掉 sticky）

50. **「谁的那些票」和「哪些日子动过」是两个维度，合成一个就会两边都错——判据还得放在能跑的那一层**（v1.19.0）。台账按人分这一版，第一版实现把 `touched` 记成一份人名清单，日子仍按"这张票哪天被动过"筛：于是 A 在 9-29 上传、B 今天提交的那张，冒进了 A 的"今天"里——A 今天根本没碰过它。他要的"今天"是他自己的工作日，不是这张票的流水。⇒ 归属必须带日期（`{名字: [日期]}`），一行同时回答"算不算他的"和"他的哪一天有它"；凡是"按 X 筛"的开关落地前，先问清 X 和已有的那条时间轴是不是同一个维度。同一轮另一条：**空态那句文案写在渲染那段里，把分支条件改成 `if(false)` 静态用例照样绿**（文案还挂在代码里，只是永远走不到）——挪进 `L.dayEmpty` 纯函数、四类各钉一条输入输出，才杀得掉这条变异。⇒ 与第 47 条同源：判据写在哪儿，决定它能不能被证明；写在模板里的是装饰，写在纯函数里的才是规则。相关：第 46 条（"这一天"认哪个字段）、第 45 条（切片边界会替隔壁蒙对）、第 43 条（静态契约看不见界面算的数）

51. **一条门问的是"有没有那条记录"，一个人问的是"是不是我"——两句话不能共用一条文案，加一档判据要同时动三处**（v1.19.1）。提交那道门查的是这张票在服务器上有没有一条录入员的**暂存事件**；录入员本人不先点暂存而直接提交，事件不存在，于是系统对一个录入员说"没有录入员复核过的暂存记录"。他问的是"当前是录入员的账号，为什么还会提示"——这句话里藏着的判断是"提示在否认我的身份"，而提示其实想说"这张票没留过核对痕迹"。⇒ 凡是面向人的提示，写完要问一句"这个人读它会以为我在说他是什么"；同一个判据对不同角色该给不同的话，而不是给同一句话让一部分人自己脑补。更要紧的是后半段：点确认后台账记 `no_inputter_review=True`，统计把它并进"跳过复核直发"的对照组——**文案别扭只是表面，数被记错才是伤**。⇒ 加一档区分（录入员本人直发）必须同时动三处：判据（服务端按会话角色分叉）、留痕（台账新键）、分档（统计新桶 `self_submit`，旧桶不再混它）；只改文案是化妆，只改统计是事后擦。同一轮还揪出确认框那半句是**前端硬接在服务器 message 后面的**（两处），服务端换文案它就变成系统在替自己撒谎——面向人的话只能有一个来源，前端只画不写。相关：第 47 条（两边各判一次就是死旗）、第 46 条（"这一天"认哪个字段）、第 50 条（判据写在哪儿决定它能不能被证明）

52. **说"界面上点不到"之前先顺着渲染走一遍；判据抄两份，两份必然走偏**（v1.19.2）。上一轮我顺着 `flagsByField()` 找到 `rest` 没人消费，就下了结论「四类红旗挂不到任何列＝看不见也点不到」——错了一半：顶部 chip 那一排是从 `effectiveFlags` 整条名单画的，每条旗都有「确认无误」。真问题小得多也实在得多：旗**挂不到列**（不显红、跳不过去、段头计数不含），以及**待办数只数行上的旗**，于是待办条能写「红旗 0」而提交门按全部旗数回 400——同一个 2026-10-12 现场，v1.17.2 只把"服务端点名的旗并进列表"那一半堵了，计数这一半一直漏着。⇒ ① 报"某东西界面上没有"之前，要顺着**画它的那段代码**走一遍，不是顺着**我以为它该走的那条链**；说重了会让人去修一个不存在的问题，还会盖住真问题（这次真问题是计数）。② 同一份判据（旗→列的五种文案形状）在 `flagsByField` 与 `chipOne` 各抄一份，就是这次走偏的机制：一处认 `L3 ` 前缀、另一处不认，旗便在 chip 上能确认、在列上永远不显红。⇒ 判据进纯函数（`L.flagKey`）、计数进唯一入口（`ticketTodo`），两边都只许调它；用例里配一条「desk.js 不许再出现第二份匹配」的静态守卫。③ 猜一条旗属于哪一列，比让它不挂列更坏：区号串边同时牵涉电话与国家、税号漏抄说"填两个 EORI 之一"，挑一个挂上去会让人去核一个本来没问题的列——所以"句里出现两个列名"一律不挂，并在 chip 上写明「不落在某一列」。④ 用例数据要能走到自己写的分支：「≥2 不挑第一个」这条规则第一版变异活着，因为我举的四类旗句里根本没有第二个列名（另两条变异则因文件是 CRLF 而压根没打上——**变异脚手架要按字节读，别用文本模式换行**）。相关：第 47 条（两边各判一次就是死旗）、第 50 条（判据写在哪儿决定它能不能被证明）、第 45 条（切片边界会替隔壁蒙对）

53. **同一份票面渲染两遍这种事，只有把分段耗时记下来才看得见**（v1.20.0）。L1 与 L2 各调一次 `img_to_data_urls`：一张扫描件白付一整轮"开文件 + 每页 pixmap + PNG 编码 + base64"，而 qc 里从前只有一个总 `elapsed`，7-20 秒的模型时间把它盖得死死的——效率审查里它是唯一一条"今天就有感知收益"的项，光读代码只能猜。修法是管道里渲染一次、两处复用（`pipeline.render_pages()`；送进模型的字节逐字相同，所以准确率口径一个字没动），并把 `timings`（render/l1/l2/l3）与 token 账一起落进 qc。**可观测性先行的价值就在这类地方**：`usage` 与 `timings` 都不参与任何判据，但没有它们，"这一秒值不值得省""开思考档多烧多少"全是拍的。相关：第 43 条（静态契约看不见界面算的数）、第 54 条（锁别锁住最贵那一步）

73. **凡是"只重画一格"的局部更新，同一张表上就不许再有逐节点挂的监听**（v1.27.1，用户："点字段后面的红旗以核按钮无任何反应，勾一下只看待核对再回去点才灵"）。这类 bug 的形状特别容易误判：判据看着是对的、值也改对了、按 checkbox 触发整页重画之后就好使——人第一反应会去怀疑状态机或缓存，其实是**监听挂在了会被换掉的节点上**：`innerHTML =` 一写，旧节点连同它身上的 listener 一起没了，新节点是"裸"的；而"勾一下才生效"恰好因为那条路径走的是整页 `render()`，`wireMain` 又跑了一遍。⇒ 规则：**一处重画、一处整页重画，两种路径都得活着**，所以同一排控件要么全走容器委托（挂在不会被换掉的 `#main` 上，只挂一次），要么局部重画之后立刻补接线——前者不会漏，本仓库选前者。写守卫时要把**两种写法都钉住**：既查"该进委托块的属性都在里面"，也查"`querySelectorAll("[data-xxx]")` 那种逐节点绑定已经从文件里消失"，只查前一条的话，有人把旧写法加回来照样绿（这正是本条 bug 的成因形状）。另一头，委托体本身也要按第 71 条钉整行语义（认哪张票、点完重画不重画、旗面取哪一份），钉属性名钉不住行为。同族第 30 条（只有浏览器能发现的那一类）——静态回归 682 全绿的那几个小时里，制单员每次改值都得"先勾一下再点"。相关：第 71 条（守卫钉整行）、第 30 条、第 69 条

74. **"混着但标得清楚"不是解决办法，而且对照物不能是"上一次的状态"**（v1.28.0，用户把 v1.27.0 的标注退回：「我们 IT 不同意，还是要原始数据，不管主单解析几次」）。两件事值得单独记：
    - **标注只是把污染变可见，没有把污染从输入里拿掉**。一个数据源同时当"凭据"和"回执"时，所有拿它当依据的东西（模型输入、逐字回查、漏取分母、统计）都还在用它——标了照样假绿。要么把它从那条链里剔出去，要么就别说自己"可追溯"。判据的对照物也同理：**"上一次读到的那批行"本身可能已被同一件事污染**（暂存之后读回来的就是脏的），拿它当基线就永远剔不掉，形成自我强化的假绿；能钉住的只有**第一次读到时就落盘、并逐次继承的那一份**。
    - **用例走的路径必须等于线上走的路径**。这轮抓到的是自己挖的洞：所有主单用例都直连 `run_master`，而审核台的路由走 `ensure`——`ensure` 会先写一份 `state=parsing` 的占位记录，那是**整份盖掉**上一份记录的。于是 v1.27.0 那个"回填标注"在线上从来没出过（占位记录的 transcript 就等于本次读到的行 ⇒ 判据永远"上次就有这行"），686 条回归一路绿灯。⇒ 新写一条判据/字段时，**至少加一条从入口（`ensure` 或 HTTP 路由）打的用例**；只测最里面那个函数，等于测了一个没人调的版本。同批还有一条：这种"整份盖掉"的占位写，必须把要继续活的账（基线、本机发过的值）显式带过去，并让用例**从占位状态回读盘上那份**（在假解析函数里 `read_master` 一次）才钉得住——第一轮我拿"最终记录"去断言，变异"占位不带基线"照样活。相关：第 72 条（同一个坑的第一半）、第 30 条（只有浏览器/现场能发现的那一类）、第 69 条

75. **"按当前值重算"这一刀，要么整排一起过，要么就明确说清哪几类不过**（v1.28.1，用户问"已经提交的票为什么还提示红旗"）。这条链上原来只有**提交那一刻**重算（门），显示侧全程用解析时那份 ⇒ 门的口径和屏上的口径不是同一件事，人对着"我明明确认过"的红旗无处可查。补上显示侧重算时有三处必须一起想清楚，少一处就是新 bug：
    - **哪些判据能对着终值算**：形态、必填、漏取都是"这一格现在是什么"，能算；**逐字保真不能**——它的定义是"模型抄的这版对不对得上转录"，人把值改过之后再拿转录去查它，报的是一片假旗。这类边界要在用例里单独钉一条（本轮 M3 就是"把保真塞进现算那份"，第一轮就活不过）；
    - **落盘那份不许就地改写**：`qc.flags` 是"这次解析错了多少"的凭据，统计读它；显示侧另开一档 `flags_now`，两处混成一个，第二天就没人能回答"到底是模型错还是数据错"；
    - **按字符串对齐的确认留痕，值一变就会失效**：这是设计里既有的代价（"改了值旧旗文案会变，自动要重新确认"），显示侧重算之后它更显眼了——现场那张票就是 2 条旧旗变 1 条真旗，剩下那条文案不同，得再点一次。所以屏上一定要写清这批旗是**按哪一版算的**（提交时刻），否则人只会觉得"软件自己改口了"。相关：第 69 条（界面状态必须等于留痕）、第 17 条（人靠哪一格核对，那一格就得是真话）、第 74 条

76. **外部审查报告的"第一档"不等于本站的第一档：先数现场，再挑条目**（v1.29.0）。那份 v3 报告 25 条逐条对过代码，行号基本都对（比 v2 准），但它的优先级表是按"票量上千"推的，而线上数过是 23 条台账 / 48 份 qc / 23M。三条判断：
    - **口径不变的先做，改业务可见行为的往后放**：压缩、循环外提、写口超时、mtime 缓存、正则预编译这五条改完没人能察觉差异；TTL 缓存会引入"别人提交了我这边 5 秒才看见"、批量并发会改输出顺序——这些是**新行为**，代价换不到今天的收益，等"哪天真的慢了"再谈。报告里那条 F1（每 tick 全量 render）确实还在，但它的另一半"renderMain 脏签名"要先由作者核对依赖清单，漏一个依赖就是漏更新，本轮没动。
    - **报告写错的要顶回去并留证据**：F4 把 `mvSave` 归错了位置；`saveDraft(t); render();` 那行是 `tests/test_server_http.py` 有意钉住的（不是"零风险改动"）；`/tmp` 那几个固定文件名是覆盖写、不是堆积；D3 的"回归时长"没有仓库内证据。
    - **加了一层就要把这一层碰过的东西重新量一遍**：GZip 挂上后 desk.js 变小只是半边，另半边是"PNG 没被二次压缩"和"`/render` 的 304 还在"——Starlette 默认跳过 `image/*`、304 走空体那条分支，所以不用配额外参数，但这是**量出来的**（隔离台 8042：`content-encoding` 无、`If-None-Match` 回 304），不是从文档推出来的。同理，`auth.load` 加缓存后必须证明"另一个进程改了 users.json 当场认出来"（本轮种子脚本正是这么撞出来的）。
