# HAWB 主分单审核台 · 技术留档

> 定位：接手这套系统时需要一次读完的**总览 + 事实清单**。
> 深水区的设计理由在三份专项文档里（见 §13 索引），本文只写"现在是什么样、为什么这样、改的时候碰哪几处"。
> 版本：v1.0.5（2026-10-02）。所有数字（字段数、用例数、端口、阈值）都是当场从代码里核出来的，不是回忆。

---

## 1. 它在解决什么业务

空运货代的**分单（HAWB）录入核对**。原始票面是扫描件 / 照片 / PDF / Excel 电子单，制单员要照着它把 40 个字段敲进公司系统 j9 AMS。这套系统做三件事：

1. **读票**：把任意形态的票面变成结构化字段（大模型读图，不是模板匹配）。
2. **兜住错**：用确定性的手段判断"模型有没有抄错/漏抄"，把可疑项标成红旗摆到人面前。
3. **可逆地写回去**：人核对完，由人点提交，走公司接口回传；系统绝不自动提交。

一句话口径（用户定案，贯穿全库）：**漏抄比多红旗严重**。宁可多报几条红旗让人确认，也不能让一个错值静默进公司库。

## 2. 数据流：四层 + 一条并行链

```
上传文件
  └─ L0 归档      store.archive_original()      output/archive/<stem>/          原件 + manifest.json
  └─ L1 逐字转录  transcribe.py                 output/transcript/<stem>.json   每行 text + bbox（归一化 0-1000）
  └─ L2 结构化    vlm_extract.py                output/raw/<stem>.json          模型直出的全字段原文口径
  └─ L3 归一化    to_air.py + codes.py          output/air/<stem>.json          航空口径（码表/清洗/拆分）
  └─ 校验         fidelity.py + validator.py    output/qc/<stem>.json           保真回查 + 红旗
                ↓
      Excel（export_excel.py）/ 数据库（db_writer.py，可选）/ 审核台（server.py + web/）
```

- **L3 是 L2 的纯函数**：改归一化规则不重跑模型，`run_batch.py --recheck` 离线重算并补红旗。
- **L1 有两条来源**：扫描件走 VLM 转录；PDF/Excel 有文字层时 `transcribe_pdf_text_layer()` 直读（pymupdf），零模型调用且 bbox 精确。
- **主单（MAWB）是并行的一条链**，不是分单链的分支：`master_pipeline.py` 吃公司检索回来的 `AMS_RECORD` 文本 → L1 拼装 → L2 提取 → 清洗/红旗 → 缓存 → `mawb2` 回传。**引擎共用，契约各管各**（分单 40 列 ≠ 主单 36 列，见 §4）。

## 4. 字段契约：改一处，别改四处

- **分单 40 列**的家是 `fieldspec.py`：`DESK_FIELDS`（key/中文名/分组）+ `GROUP_LABELS`（单号 / 航路 / 货物与日期 / 发货人 SHIPPER / 收货人 CONSIGNEE）+ 类型表 `NUM` + 长文本表 `LONG`。
- 审核台表头那一块由 `deploy/gen_fields.py` 生成进 `desk.js` 的 `/* ==FIELDS== */ … /* ==/FIELDS== */` 区间；`--check` 用于查漂移（回归里有断言）。
- **主单 36 列**在 `master_fields.py`，列名必须跟公司 `AMS_RECORD` 逐字一致（IT 改过一次：`NOTIFYE_INFO_COUNTRY` → `NOTIFY_INFO_COUNTRY`，跟着改过一次）。
- 加/删一列要同时动：字段表 → prompt → L3 摘取 → 形态校验 → 保真正反查 → 审核台 → `schema.sql`。**回归里有 AST 扫描盯着硬编码列数**，散落的 `39`/`40` 会被抓。
- 老库要手工 `ALTER`：`schema.sql` 只做 CREATE，历史表补列在它注释掉的「老库升级」段里。

## 5. 模型渠道（L2 用什么读票）

预设表在 `config.MODEL_PRESETS`，四家，顺序即下拉顺序（2026-09-24 定案）：

| 预设键 | 渠道 | 实测结论（二十票横评，2026-09-24） |
|---|---|---|
| `intern-s2-official` | 官方书生 API（`chat.intern-ai.org.cn/api/v1`） | **默认**。约 7-10 秒/张，无配额墙 |
| `qwen38-flash-bailian` | 阿里云百炼（按 token 计费） | 保真 409/410、红旗 9 条，优于 S2 的 409/412、12 条；比 S2 慢约 3 秒/票；预设里已关思考 |
| `mimo-v2.6-flash` | 小米 MiMo | 与 S2 平级，但 p90 45-70s 长尾 + 出现过一次 HAWB_NO 静默错填 |
| `doubao-seed-2-1-lite` | 火山方舟 | 开思考 97-124 秒/票，只适合当"第二只眼睛"复核 |

- **主单链单独一个开关** `MASTER_VLM_MODEL`，默认 `qwen38-flash-bailian`。理由：主单输入是几百字符纯文本、没有票面图，同一条主单 S2 花 97.8 秒只取到 2/36 列，qwen 7 秒取到 17/36。**别拿分单横评去推主单**。
- 换渠道的两种方式：审核台顶栏下拉热切（管理员）/ 改 `.env` 重启。缺密钥会在解析时直接报"渠道缺密钥"，**不静默回退**。
- 纯文本模型（`VLM_VISION=0`）机制保留但不推荐：它收到图片会把票面**编**成别的内容。扫描件会明确报错，电子单/文字层 PDF 可直读。
- 超时策略：`VLM_TIMEOUT=300`，超时只重试 `VLM_TIMEOUT_TRIES=2` 次（慢模型重跑还是五分钟，连撞三次只是把人钉在等待上），其他错误按 `VLM_RETRIES=3` 退避。
- 每个预设必须带 `max_tokens` 下限：实测有单次推理烧掉 19309 输出 token 的票，8192 被掐死 → content 空 → 连败三次。

## 6. 公司系统 j9 AMS 对接（唯一会写外部数据的地方）

四个路径（**末尾斜杠是接口契约的一部分**，少斜杠会 404）：
`POST /api/v1/j9/hawb`（读分单行）、`/api/v1/j9/hawb2`（写分单）、`/api/v1/j9/mawb/`（读主单）、`/api/v1/j9/mawb2/`（写主单）。两把 key 互不通用：`COMPANY_MAWB_KEY` / `COMPANY_HAWB_KEY`，只进 `.env`。

四条硬规矩（都在 `company_api.py`，都有用例）：

1. **先读后写**：提交前先 `j9/hawb` 读回那一行，读不到就拒（不能凭本地数据猜公司侧状态）。
2. **SEND_STATUS 闸门**：只有 0/2 可更新，1 是已发送/锁定 → 拦下并说明，绝不发 `hawb2`。另注意 `SEND_STATUS=0` 在公司侧含义是"已录入待发送"，**不等于"从没动过"**，界面两栏要分开显示。
3. **整表写回**：公司接口是整表覆盖，没提交的列会变 NULL → 读回来的原值必须一起带上。
4. **幂等锁** `GUARD_TTL = 90`：同键同内容 90 秒内不重复写（`output/submit_guard/`，一锁一文件）。

限流与重试：IT 文档写每把 key 10 次/秒，本地默认 `J9_RATE_PER_SEC=8` 留两成余量；读 10s / 写 20s 超时；429/5xx/连不上退避重试 `J9_RETRIES=3`，**400 业务错不重试**。`COMPANY_API_MODE=mock` 时只回本机回执不外发（默认）。

公网是 http 明文，所以两把 key 按"可轮换"对待。

## 7. 审核台前端（形态③，日常主入口）

- **零构建**：`logic.js` 装纯逻辑（全局 `L`，尾部一行 `module.exports` 只为让 node 能读），`desk.js` 只碰 DOM。`index.html` 里 logic.js 必须排在 desk.js 前面（有断言）。
- **子路径自适应**：`BASE = location.pathname.replace(/\/(index\.html)?$/, "")`，所以挂在 `/hawb/` 下和根路径下都能用；静态资源走 `/web/{asset}`，`no-store`。
- **两个视图**：核对工作台 / 今日台账（`/day`，按日期聚合当班录入与红旗）。左侧 48px 状态窄轨 + 置顶待办条 + 底部常驻操作条。
- **票面浏览演进（重要）**：早期把 PDF 交给浏览器内嵌阅读器，结果 ① Chrome 的缩略图侧栏吃掉近一半宽度；② 窄高栏里 `view=Fit` 与 `view=FitH` 算出**同一个缩放**，按钮点了没反应；③ Edge 完全不理 `navpanes=0`，侧栏关不掉。v1.0.3 起**票面一律走我们自己的 `/render` 页图**（服务端 pymupdf 按页转 PNG，页数从响应头 `X-Ticket-Pages` 拿），v1.0.4 加"按住拖动"，v1.0.5 加"滚轮缩放"。
  - 缩放算式全在 `logic.js`：`wholePagePct`（整页所需图宽，占栏宽百分数）、`maxZoomPct`（不许超过渲染像素，A4@scale2 在 675px 栏位 = 176% 见底）、`zoomStep`（滚轮乘法步进 ±15%，25–400%）、`zoomAnchor`（钉住光标下那一处）、`canPan`（内容真超出才给抓手）。
  - 两条反复强调的判据：**不给"看着能拖其实拖不动"的假抓手**；只剩一档的按钮就藏掉。
  - 监听滚轮必须 `{passive: false}`，否则 `preventDefault` 被忽略、滚轮还是去滚整页。
  - 只有拿不到归档（没勾「落盘留档」）才退回浏览器阅读器，那条路径保留三档循环（`pdfBox`/`viewCycle`/`firstView`）。
- **点字段定位票面**：点右侧字段名 → `/layout/{stem}` 取 L1 行 bbox → `/render` 页图打底 → 高亮 + 自动放大到约占窗格 1/3。
- **草稿**：编辑存本机 localStorage（`L.draftMerge/draftPut`），提交成功后仍可回看；解析值与草稿原值不一致的列才算"打架"，不无脑覆盖。
- 主单视图借同一对面板，但那一栏是"资料文本"不是票面图，点字段不能定位——界面上写明了。

## 8. 登录、账号与安全边界

- 登录是**唯一**门禁（`auth.py`）：pbkdf2 口令哈希 + HMAC 签名会话 Cookie；`users.json` 存哈希与 secret。历史上的 `HTTP_API_KEY`/`X-API-Key` 已连根删除。
- 三角色：`admin`（可切模型、管账号）/ `reviewer` 制单员（上传、核对、提交）/ `inputter` 录入员（主单检索与提交）。`require_web` / `require_admin` 只认会话。
- 首启种下 `admin/admin123` + 8 位制单员（种子口令为空，登不进）+ 3 位录入员。**上线第一件事：改 admin 口令并给制单员下发口令**。
- 密钥与本机文件：`.env`、`users.json`、`output/`、`input/`、`_quarantine_20260920/`、IT 那份带真 key 的《AMS录入接口调用说明》全在 `.gitignore` 里，并有 `tests/test_gitignore.py` 拿 `git check-ignore` 逐个问一遍（源码文件被误挡也会红——部署清单取自 `git ls-files`）。
- 提交动作只由人点。回传失败的原因会带票号落到服务日志（`journalctl -u hawb-desk` 可查），不只在响应里一闪而过。

## 10. 测试体系（324 项，零 pytest）

- 入口 `python -X utf8 tests/run_tests.py [过滤词]`，自定义 runner，35 个 `tests/test_*.py` 自动发现。
- **离线**：不打真实模型、不连公司系统（`mock` 模式 + 桩）。真调用类的验证另放 `poc/`（目前只剩主单模型横评 `poc/master_model_compare.py`，跑一次花额度）。
- 前端纯逻辑用 **node 驱动**（`tests/web_src.py` 的 `logic()`），不引 jsdom；机器上没 node 算**失败**，不算跳过。
- 静态契约扫描是一类重要用例：`test_imports.py`（跨模块私有调用、退役层复活）、`test_fieldspec.py`（字段块漂移、硬编码列数）、`test_server_http.py`（页面里所有 fetch 必须带 `BASE` 前缀、`[hidden]` 必须有 CSS 兜底、`/health` 字段）、`test_env_doc.py`（`.env.example` 覆盖所有真实配置键）、`test_console.py`（GBK 控制台可读性）。
- 惯例：**先写红用例再动手**；改完跑全量；关键闸门要做**变异验证**（把规则删掉看测试是否真的红——"闸门自己也要被验证"）。
- L3 基线：`fixtures/l3/{input,expected}`，有意改归一化后 `--update-baseline` 复核差异再更新。

## 11. 部署与发版（这台机器 → efreight-vm）

服务器：`efreight-vm`（SSH 别名，ubuntu@82.157.193.231），**多服务共用生产机**（ccsp / efreight-license / jrt-api / dsv-mail），所以新服务一律绑回环、避让 8000/8010、带内存闸。

- 服务：`hawb-desk.service` → `.venv/bin/python server.py --host 127.0.0.1 --port 8020`，`Restart=always`、`MemoryHigh=900M MemoryMax=1300M`。
- 入口：nginx 443 反代 `location /hawb/` → 剥前缀转 8020（自签证书，浏览器会告警）。对外 `https://82.157.193.231/hawb/`。
- 环境：`requirements-server.lock.txt`（31 个精确 pin）复现服务器；`deploy/README-ubuntu.md` 是重装手册。

**`deploy/sync.sh` 是一条链，不是 scp**：备份 → 推（tar 管道，`.env` 走 stdin 不落地）→ 逐文件 md5 核对 → 按 `.deployed-files` 删服务器上已删的文件（tar 不会删，漏过一次"部署成功但线上有孤儿模块"）→ 在 VM 的 `.venv` 里跑全量回归并**带回真实退出码** → 重启 → `/health` 自证（含 `version` 与本机 `config.APP_VERSION` 一致）。参数：`--no-restart`（只改了 css/js/文档时，拒绝在非测试 `.py` 变更时使用）、`--dry-run`、`--allow-dirty`。

**发版一条命令**：`./deploy/release.sh <x.y.z>` = 改号 → 本机 `.venv` 全量回归 → 提交并打 tag → `sync.sh` → 独立再查一次线上 `/health` 确认版本 = 刚打的号 → 推 GitHub。号怎么定：修 bug/重构 +0.0.1，界面与字段口径 +0.1.0，换形态 +1.0.0 并改 `config.FORM`。

GitHub：`origin = git@github.com:jy3398739/jrt-hawb-desk.git`（**私有**）。这台机器与 VM 到 `github.com` 的 HTTPS 都被掐（`api.github.com` 通、SSH 通），所以只能走**部署密钥 + SSH**，`gh` 设备码流程无效。已推 `v1.0.0`–`v1.0.5`。

## 15. 踩过的坑（这一节最值钱，改代码前扫一眼）

1. **闸门自己也要被验证**。`sync.sh` 的回归闸门曾是空的（`| tail -3` 让退出码变成 `tail` 的 0），"部署成功"却没人跑过测试。同类：`tar` 不删远端已删文件 → 线上留孤儿模块。
2. **Windows 控制台是 cp936**。把 stdout 强改 UTF-8 不崩，但用户看到的是一整屏乱码；只设 `errors="replace"`。`.bat` 是 GBK+CRLF，**绝不能用按 UTF-8 读写的编辑器改**（有断言要求"仍能按 GBK 解码"）。
3. **别用 heredoc 写含中文/反斜杠的源码**：`\b` 会落成退格符，正则照旧编译通过却谁也匹配不上。
4. **`git commit -m "..."` 里别放反引号**：双引号内的 `` ` ` `` 会被 bash 当命令替换执行，提交照样成功但那半句没了。
5. **ssh 远端命令的退出码会被管道最后一条吞掉**，本地 `pipefail` 管不到远端 shell；要判成败就 `; echo \$?` 带回来。
6. **真实票名带 U+00A0 不间断空格**（`016-82445790\xa0分单`），手敲普通空格去调 `/render` 会 404；票面里的连字符常是 U+2010，重音字母会拆码位。
7. **改 `.py` 必须重启服务**，而重启会踢掉在线会话；css/js/文档用 `--no-restart`。出现过"服务端跑的是旧进程、新功能像坏了"的静默失效，`/health` 的 `stale_files` 就是为此存在。
8. **阅读器的地址参数两家不通用**：Chrome 认 `navpanes=0`，Edge 完全不认（只认 `toolbar=0`）。凡是把表现交给第三方内嵌组件，就要按"最保守那家"设计，或干脆自己渲染。
9. **界面控件点了必须有反馈**。"两个选项在某种版式下算出同一个结果"就是死按钮（`Fit`/`FitH` 撞车、抓手残留），判据要写进测试。
10. **口径别替用户放大**：USCI 可以填 EORI，不等于"什么号都能塞 EORI"；主单税号非 USCI 的那类要问 IT，不猜。
